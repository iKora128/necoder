## 怒り駆動開発

とにかく私の開発スタイルは怒り駆動です。

私の怒りは割と明確でした。

- Electronが重すぎる。メモリ管理に気を使う
- 複数のプロジェクトを一つのWindowで管理したい
- 最初から複数のAI Agentが使えるようにしてほしい
- どのプロジェクトに自分がいて、どのAIに指示を入れているかわかりやすくしてほしい

一方でCursor自体は割と気に入っていますし、個人的にはClaude Code拡張機能がかなり好きで、この使い勝手については手放したくないなと思っていました。
https://code.claude.com/docs/ja/vs-code

### 求めたもの

実は最初、自作する気はまったくありませんでした。まずZedに乗り換えて、設定でなんとかしようとしたんです。

で、settings.jsonを掘り尽くした結果わかったのは、**欲しいものが構造的に存在しない**ということでした。

- Zedの拡張機能はUIを描けない。作れるのは言語・テーマ・アイコン・スニペット・デバッガ・MCPサーバの6種類だけで、「スレッドに色を付ける」「タブを足す」は原理的に不可能
- スレッドやプロジェクトごとの色分け機能は、ソースを検索してもゼロ
- per-windowテーマ（VSCodeでいうPeacock相当）のPRは存在するものの、レビューで止まったまま塩漬けらしい

つまり、設定でも拡張でもforkでも埋まらない。要望を出して待つ手もありましたが、UI拡張はZedチームも「慎重に自分たちの手でやる」と言っている領域で、いつ来るかわかりません。

じゃあ作るか、となりました。整理すると、求めたものはこの4つです。

1. Claude Code拡張の使い勝手（⏺のトランスクリプト、トークン表示）をそのまま持ってくる
2. Electron抜きのネイティブの速さ
3. 1ウィンドウに複数プロジェクト・複数ブランチ
4. 今どこにいるかが色でわかること

## UI哲学

既存の延長線上に答えがないなら、一から設計するしかありません。
`necoder`では、UIの原則を根本から見直し、以下のルールを徹底しました。

- **並列作業は横へ:** ブラウザの従来のタブ概念を借用し、同一プロジェクト内のタスクを横に展開する
- **並行作業は縦へ:** Slackのワークスペース概念を借用し、プロジェクト間の切り替えを縦に配置する
- **方向感覚としての色:** プロジェクト・AIエージェントタブごとに識別色を持たせ、今自分がどこにいるか、認知負荷が低い形で認識させる

昨今出てくるエディタやツールの多くが、**この縦と横、並列並行の感覚を失っていること**に気が付きました。
結果、ユーザーはVertigo（空間識失調）になり、余計な動作や、本来指示するべきでないAIエージェントに指示を出してしまうのです。

色については、もうひとつルールを足しました。**色は識別にしか使わない**。レール、タブの下線、キャレット、スレッドのチップ。そこにだけプロジェクトの色を流して、グラデーションや装飾には一切使いません。全部に色を塗ると、色が方向感覚として機能しなくなるからです。

## 採用技術

RustとGPUIです。GPUIはZedが自分たちのために作っているUIフレームワークで、GPU描画のネイティブUIをRustで書けます。

Electronへの怒りから始まっている以上、Tauriのようなwebview系は最初から除外でした。Tauriは軽いんですが、編集コアの性能は結局webviewに縛られます。webviewはZedが速さのために捨てたモデルなので、そこに戻るなら自作する意味がない。

ただ、GPUIの採用は正直タダではありませんでした。

- **crates.ioに安定版がない。** Zedリポジトリからgitのrev固定で引っ張ってきます。APIは予告なく変わるので、revを上げるときは追従修正とセット
- **ドキュメントが薄い。** 一番のユーザーがZed自身なので、入門記事的なものはほぼ無く、Zedのソースコードを読んで書き方を学ぶのが実態です。ネット記事や、AIが記憶で書いてくるGPUIのAPIは大体古くて動きません
- **非Zedの事例が少ない。** 詰まったら自力です

会社が看板製品用の内製エンジンをOSS公開している状態、と言えば伝わるでしょうか。モノは本物ですが、「あなたのため」には整備されていません。それでもZed級の描画速度が手に入るなら払う価値がある、という判断です。

エディタの中身は、枯れた部品を組み合わせています。

| 何 | 使ったもの |
|---|---|
| テキストバッファ | ropey（rope構造） |
| シンタックスハイライト | tree-sitter（インクリメンタルパース） |
| 言語知能 | LSP（rust-analyzerなどをそのまま起動） |
| 統合ターミナル | alacritty_terminal |
| AIエージェント接続 | ACP（agent-client-protocol） |
| チャットのMarkdown描画 | pulldown-cmark + 自作レンダラ |
| ローカル永続化 | Turso（pure-RustのSQLite再実装） |

なお「スクラッチに近い」と書きましたが、ZedのGPLアプリケーションコードはコピーも翻案もしていません。エディタ本体はnecoderの型と要件から独立に実装して、AGPL-3.0で公開しています。

罠も踏みました。一番笑ったのは`target/debug`が**95GB**まで膨らんだことです。GPUI級の依存ツリーでcargo既定のフルデバッグ情報を持つとこうなるらしく、`debug = "limited"`に落として解決しました。行番号付きバックトレースは残るので実用上は困りません。

## AIエージェントとの作り方

このエディタ、コードの大半はClaude Codeが書いています。7月中旬に着手して、今7週間ほどです。

医者からエンジニアになった自分が、person-decades級と言われるエディタ自作を1人で回せているのは、進め方をドキュメント駆動に振り切ったからだと思っています。仕組みはこうです。

- **設計文書4枚を正とする。** ROADMAP（受入条件）、ARCHITECTURE（crate構成）、UI-SPEC（色とレイアウトの仕様）、そして見た目の正であるHTMLモック
- **`/goal`という自走コマンドを作る。** 打つと、エージェントがROADMAPの次の未チェック受入条件を選び、実装して、検証して、ROADMAPと日誌を更新するところまでやる
- **UIはスクリーンショットで検証させる。** ヘッドレスでアプリのスクショを撮るスクリプトを用意して、エージェント自身に画像を見せてレイアウト崩れを確認させる

実装と文書がズレたら、文書を直す方が先。このルールだけは守っています。エージェントに書かせる開発では、コードよりドキュメントの方が資産です。

そして途中からは、necoderの中でnecoderを開発しています。使っていて気になったところが、そのまま次の怒り、じゃなくて次のタスクになる。ドッグフーディングと怒り駆動は相性が良いです。

## どこまで動くのか

「自作エディタ」と聞くと、おもちゃを想像すると思います。実測値を置いておきます（開発機・Apple Silicon）。

- コールドスタート **約215ms**
- アイドル時メモリ **約120MB**（Cursorを10窓開けていた人間からすると別世界です）
- 編集コアの操作 **約1µs**（CIで性能予算をガード）
- ⌘Pのファイル検索、5万件の絞り込みで **約10ms**

エディタとしての基本機能もひと通りあります。LSP（診断・補完・rename・code actions・整形）、tree-sitterハイライト、Git（ガターdiff・hunk stage・blame・worktree管理）、統合ターミナル、プロジェクト全体検索、マルチカーソル、日本語IME、hot exit。Remote SSHは約2.4MBの静的バイナリをサーバ側に置く方式で、どちら側にもnodeが要りません。Windows版もあります。

肝心のAI部分は、ACPでClaude Codeがエディタの中で動きます。色付きスレッドタブ、宛先チップ（スレッド名 + プロジェクト ⎇ ブランチ）、トークン常時表示、diffレビュー、チェックポイントからの巻き戻し、並行エージェントを一覧する編隊ビュー。既存のClaude Codeサブスクを`claude` CLI経由でそのまま使うので、APIキーは不要です。

もちろん足りないものは山ほどあります。デバッガはまだ無いし、拡張機能のエコシステムなんて当然ありません。それでも冒頭に書いた通り、半分以上の作業はもうnecoderでやっています。自分の怒りに対する回答としては、十分動いています。

## おわりに

エディタ自作は、始める前は完全に無謀枠でした。Zedは一流チームが資金と年数をかけて作っているし、個人発のLapceやHelixも、数年かけてなおニッチというのが相場らしいです。

それでも今は、AIエージェントに設計文書を渡して受入条件を消化させる、という戦い方があります。7週間で「毎日使うエディタ」まで来られたのは、時代の恩恵以外の何物でもありません。

necoderはAGPL-3.0でソースを公開しています。macOS（Apple Silicon）とWindowsのビルドがあるので、Cursorのウィンドウを10個開いている心当たりのある方は、ぜひ触ってみてください。
