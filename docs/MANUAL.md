## 1. インストールと初回起動

### macOS 13 以降（Apple Silicon）

1. [Releases](https://github.com/iKora128/necoder/releases) から `necoder.dmg` を取得する
2. **necoder** を「アプリケーション」へドラッグする
3. 起動する。署名・公証済みで、以後の更新はアプリ内で行われる（適用前に Apple 署名を検証する）

### Windows 10 以降（x64）

1. Releases から `necoder-windows-x64.zip` を取得して展開する
2. `necoder.exe` を実行する。新版が出るとアプリ内で通知され、リリースページを開ける

### AI 機能を使う準備

AI 機能は [`claude` CLI](https://docs.anthropic.com/en/docs/claude-code)（Claude Code）を経由して動く。
CLI をインストールしてログインしておけば、**API キーは不要**（既存の Claude Code の契約をそのまま使う）。
初回起動時の「ようこそ」画面にエージェントの一覧と導入状況が出るので、そこから始められる。

### ターミナルから開く（`ne` コマンド）

1. **設定（⌘,）→ AI エージェント → コマンドライン** で `ne` をインストールする（macOS の認証を許可）
2. ターミナルで `ne .` を実行する

necoder が起動中ならそのウィンドウで開き、起動していなければアプリを起動する。
`ne src/main.rs:42` で 42 行目へ、`ne --diff a.txt b.txt` で 2 ファイルの差分を開ける（[§16](#16-コマンドラインne)）。

## 2. 画面の見かた

```text
┌ titlebar: ● プロジェクト ⎇ branch ▾ | Editor | Fleet | Chat |     実行中スレッド   [ドック開閉] ┐
│レール│ 左ドック（エクスプローラ等）│ タブ / エディタ               │ 右ドック（Agent パネル） │
│ ●    │                          │                               │                        │
│ ●    │                          ├ 下ドック（ターミナル）         │                        │
└ statusbar: ⎇ branch · 診断 · ターミナル · 実行状況のまとめ · 更新 · 行:列 · 言語 ─────────┘
```

### 色の意味（これだけ覚えればよい）

necoder は色を**識別のためだけ**に使う。装飾には使わない。

| 色 | 何を表すか | どこに出るか |
|---|---|---|
| **プロジェクト色** | 今どのプロジェクトにいるか | 窓の縁・レールの枠・アクティブタブの上線・キャレット・選択の左バー |
| **スレッド色** | どの AI スレッドと話しているか | スレッドタブ・宛先チップ・composer の枠・送信ボタン・トークンメーター |

エージェントの状態は**色ではなく形と動き**で表す。

| 形 | 状態 |
|---|---|
| ⠋⠙⠹（回る点字） | 作業中 |
| ◐ 半円・速い脈動 | 承認待ち・質問待ち（あなたの操作が必要） |
| ✓ リング・静止 | 完了・未確認 |
| ○ 淡い点 | 待機 |

### 主な領域

- **レール**（左端の縦列）: 開いているプロジェクト。下部にエクスプローラ / 検索 / Git / Todo / AI / ターミナル / SSH のアイコン
- **titlebar のピル**: 名前をクリック = プロジェクト切替（⌘O）、`⎇ branch ▾` = ブランチ / worktree メニュー
- **statusbar 中央**: 全プロジェクトの「N 実行 · M 承認待ち · K 完了」。クリックで該当スレッドへ飛ぶ

## 3. プロジェクトを開く・切り替える

| やりたいこと | 操作 |
|---|---|
| フォルダ・ファイル・リモートを開く | レールの **＋**（最近開いたものも一覧に出る） |
| 開いているプロジェクト間を移動 | **⌘O**（プロジェクトとブランチ / worktree の 2 階層一覧） |
| n 番目のプロジェクトへ | **⌘1〜⌘9** |
| 前後のプロジェクトへ | **⌃⌘↑ / ⌃⌘↓** |
| 連続で流し見する | レールを 1 回クリック → **↑ / ↓**（Esc で作業面に戻る） |
| 新しいウィンドウで開く | ⌘O 内で **⌘⏎** / **⌘⇧N** |
| ブランチを別フォルダで並行作業 | ピルの `⎇ ▾` →「＋ ブランチを worktree で開く」 |

キー操作で切り替えると、画面中央に行き先の「プロジェクト名 ⎇ ブランチ」が約 1 秒表示される。

**レールの右クリック**: 色の変更 / 新しいウィンドウで開く / パスをコピー / ブランチ名をコピー / レールから外す /（worktree のみ）worktree を削除。Fleet サイドバーの Task 行の右クリックも同じメニュー。

### プロジェクトのアイコンと色

- `.necoder/icon.png`（jpg / webp も可）を置くと、レールのアイコンになる
- 色は自動で割り当てられる。変えるには **⌘K ⌘C** またはレールの右クリック。任意の hex も入力できる
- 色はプロジェクトに付く。レールの並び順・ウィンドウ・再起動では変わらない

## 4. ファイルを編集する

### ファイルを開く

- **⌘P**: ファイルファインダ（あいまい検索）。最近開いたファイルが上に来る。`.gitignore` で隠れたファイル（`.env` や `build/` の中など）は、何も一致しない時に出る「無視されたファイルも探す」を選ぶと探せる
- **⌘⇧P**: コマンドパレット（全コマンドを名前で実行）
- エクスプローラ（左ドック）: ツリー / カラム / アイコンの 3 表示をフッタで切り替える

**エクスプローラの操作**

- **1 回クリック = プレビュータブ**（タブ名が斜体）。次に 1 回クリックしたファイルがそのタブを置き換えるので、眺めて回ってもタブが溜まらない。**ダブルクリック**・編集・タブのダブルクリック・ピン留め・⌘P で開き直すと普通のタブになる。いつも普通のタブで開くなら 設定 › 動作とエディタ の「プレビュータブ」を切る（`preview_tabs: false`）
- 右クリック: 開く / ここをプロジェクトとして開く / 分割して開く / Finder に表示 / パスをコピー（⌥⌘C）/ 名前を変更（⏎）/ ゴミ箱に入れる（⌘⌫）
- フォルダの右クリック: **フォルダ内を検索**（⌘⇧F の検索をそのフォルダに絞って開く）
- 変更のあるファイルの右クリック: **ステージ** / **変更を破棄…**（確認してから最後のコミットの内容に戻す。git の管理外のファイルはゴミ箱へ入れるので ⌘Z で戻せる）
- ドラッグ: エクスプローラ内の移動は **移動**、Finder からのドラッグは **コピー**。同名ファイルは上書きしない
- **⌘Z**（エクスプローラを押した状態で）: ファイル操作を新しい順に 1 つずつ取り消す。対象は新規作成・名前の変更・移動・複製・Finder からのコピー・ゴミ箱に入れる（Esc でエディタへ戻る）
  - ゴミ箱に入れたものは、ゴミ箱から元の場所へ戻す。ゴミ箱を空にした・Finder で戻した等でゴミ箱に無いときは、戻せないと表示する
  - 作成を取り消すと、空のファイル・フォルダは消え、中身があるものはゴミ箱へ入る
  - 戻し先に同じ名前があるとき・開いているファイルに保存していない変更があるときは戻さない
  - エディタにフォーカスがある時の ⌘Z は、これまでどおり文字の取り消し
- 右上の ↻: 外部（エージェント等）が作ったファイルが見えないときに読み直す

### 編集の基本

| キー | 動作 |
|---|---|
| ⌘S | 保存 |
| ⌘Z / ⌘⇧Z | 元に戻す / やり直し |
| ⌘D | 同じ語を次も選択（マルチカーソル） |
| ⌥⌘↑ / ⌥⌘↓ | 上 / 下にカーソルを追加 |
| ⌥↑ / ⌥↓ | 行を上 / 下へ移動 |
| ⇧⌥↑ / ⇧⌥↓ | 行を上 / 下へ複製 |
| ⌘⇧K | 行を削除 |
| ⌘/ | コメント切替 |
| ⌘] / ⌘[ | インデント / 逆インデント |
| ⌥Z | 折り返し表示の切替 |
| ⌃G | 行番号へ移動 |
| ⌃- / ⌃⇧- | 移動履歴を戻る / 進む |
| ⌘\ | 右に分割 |
| ⌘W / ⌘⇧T | タブを閉じる / 閉じたタブを復元 |
| ⌘K ⌘W | タブを全部閉じる（未保存のタブとピン留めしたタブは残す） |
| ⌘K ⇧⏎ | タブをピン留めする / 外す（ピン留めは左端に並び、まとめて閉じても ⌘W でも閉じない。外すにはピンを押す） |
| ⌘⌥C | 開いているファイルの `path:行` をコピー（選んでいれば `path:10-14`。エージェントへの指示に貼るとリンクになる） |
| ⌘} / ⌘{ | 次 / 前のタブ |

emacs 風の移動（⌃A ⌃E ⌃N ⌃P ⌃F ⌃B ⌃K など macOS 標準のもの）も使える。

開いているファイルを**ほかのエディタで開く**: パレットの「外部: VS Code で開く」「外部: Cursor で開く」「外部: Zed で開く」（今の行まで開く・`code` / `cursor` / `zed` コマンドが要る。無い macOS はアプリでファイルだけ開く）、「外部: ターミナルでフォルダを開く」。SSH 先のプロジェクトでは使えない。

### リソース（メモリ）

パレットの「リソース: メモリとプロセス」で、necoder 本体と、necoder の中で動いているプロセス（エージェント・ターミナル・言語サーバ）のメモリがプロジェクト / Task ごとに出る。重いプロジェクトに「使っていないエージェントを止める」が出ていれば、押すとそのプロジェクトの静かなエージェントを止める（会話は残り、次に送ると続きから再開する。走行中・承認待ち・送信待ちのスレッドは止めない）。一覧は開いた時と ↻ を押した時だけ読む。SSH 先のプロセスはまだ出ない。

### 開いているポート

パレットの「Ports: 開いているポート」で、necoder の中（ターミナル・エージェント）で立てた開発サーバのポートが出る。どのプロジェクト / Task のものかは色の点で分かる。`開く` で necoder の Web タブに、`止める` でそのサーバを止める（necoder の中のプロセスだけ）。ほかのアプリのポートは「ほかのプロセス」に畳んである。一覧は開いた時と ↻ を押した時だけ読む。SSH 先のポートはまだ出ない。

### プレビュー

`.md` と `.html` は **⌘⇧V** でソースと表示を切り替えられる。HTML は OS 標準の WebView（macOS は WKWebView、Windows は WebView2）で表示する。

Markdown のプレビューのリンクは押せる。URL はブラウザ（localhost なら下の Web タブ）で、ファイルへのリンクはタブで開く。

### 開発サーバを見る（Web タブ）

`npm run dev` などで立てた開発サーバは、エディタのタブで見られる。

- **⌘⇧P →「プレビュー: localhost を開く…」** でポート番号（`5173`）か localhost の URL（`localhost:3000/app`）を入れる
- エージェントの会話や Markdown に出てきた `http://localhost:…` のリンクを押しても開く
- ツールバー: 戻る / 進む / 再読み込み / ズーム（− 100% +）/ 幅（全幅・375・768・1280）/ DevTools / 既定のブラウザで開く
- 開けるのはこのマシンの `localhost` / `127.0.0.1` / `[::1]` だけ。ページの中で外部のサイトへ移動しようとした時や、新しい窓を開こうとした時は、既定のブラウザで開く
- 開いていた Web タブは再起動しても戻る。サーバが起動していない時は「接続できませんでした」と出るので、起動してから再読み込みする

#### 画面の要素を AI に見せる（Design モード）

「このボタンをもう少し小さく」のように、見えている要素を指して頼める。

1. Web タブのツールバーの **Design**（または **⌘⇧D**）を押す
2. ページの上でマウスを動かすと、下の要素に枠と名前が出る。**クリック**で選ぶ（**Shift+クリック**なら続けて何個でも選べる）
3. 選んだ要素は、アクティブなスレッドの入力欄に「◎ 要素の名前」の画像チップと説明の文章として入る。**送信はされない**ので、指示を書き足して ⌘Enter で送る

- 説明には、セレクタ・位置と大きさ・主なスタイル・テキスト・HTML の抜粋と、React なら部品の名前とソースの場所（開発ビルドの時）が入る
- パスワード欄の値や、トークン・API キーらしい属性は伏せて入る。URL の `?` 以降も落とす
- Esc かもう一度 Design を押すと終わる

### AI インライン編集（⌘I）

1. コードを選択して **⌘I**
2. 指示を入力して Enter
3. 差分を見て **⏎ で適用 / Esc で破棄**

ターミナルで ⌘I を押すと、指示からコマンドを生成する。

### 自動保存

設定 › 動作とエディタ の「自動保存」（`auto_save`）で選ぶ。既定は「しない」（⌘S だけ）。

| 値 | いつ保存するか |
|---|---|
| しない（`off`） | ⌘S の時だけ |
| 他へ移った時（`focus_change`） | 別のタブ・パネル・窓・アプリへ移った時 |
| 手を止めた時（`after_delay`） | 上に加えて、打つのを 1 秒止めた時 |

エージェントや別のエディタがファイルを書き換えて「外で変更されました」と出ているタブは、自動では上書きしない（読み直すか、⌘S で上書きするかを選ぶ）。自動保存ではフォーマットしない。necoder の設定ファイル（settings.json・keymap.json・`.necoder/` の中）は、書きかけで反映されないよう、手を止めただけでは保存しない。

### 未保存のまま終了しても消えない（hot exit）

未保存の変更を残して終了しても、次回起動時に「前回終了時の未保存の変更があります」と出て **復元** できる。

## 5. 検索

| キー | 範囲 |
|---|---|
| ⌘F | このファイル内。Enter / ⇧Enter で次 / 前、`Aa` で大文字小文字、`.*` で正規表現 |

## 7. Git とターミナル

### Git（ソース管理パネル・⌃⇧G）

- エクスプローラとガター（行番号の横）に変更が色で出る
- **F7 / ⇧F7**: 次 / 前の変更箇所（hunk）へ。hunk 単位でステージ・取り消しができる
- パネルの変更の行を押すと、そのファイルの diff をタブ（`<名前> ⇄ HEAD`）で開く。行の右の ＋ / − はステージ / 解除
- パネルでステージ → メッセージ入力 → **⌘⏎ でコミット**。メッセージ欄は Enter で改行、⌘V・⌘Z・日本語入力が効く。メッセージは AI に生成させることもできる
- コミットと push では、その repo のフック（pre-commit・commit-msg・pre-push）が走る
- コミット・push・pull・PR などが失敗すると、理由（git / gh の出力の要点）がトーストに出る。フックの出力のように長いときは、トーストを押すと全文をタブで開ける
- ブランチの作成・削除、worktree でレールに開く、GitHub で PR を作成（`gh` が必要）
- blame、diff タブにも対応。差分が無いときは diff タブを開かずトーストで知らせる。削除されたファイルは題名に「削除」と出る

### 変更レビュー

変更したファイルを全部 1 画面で読む。パレット「**Git: 変更をレビュー**」か、ソース管理パネルの「**⇄ 変更をレビュー**」でタブとして開く。
Fleet では Task カードの「**変更**」タブが同じ画面になる。

- 左のツリーでファイルを押すと、その位置へ飛ぶ。`☰` でツリーを隠せる
- 追加した行は緑、消した行は赤の薄い面。左の 2 列が旧・新の行番号
- 変更の無い所は `⋯ N 行` に畳まれている。押すと前後 20 行ずつ開く
- 「**比較**」で何と比べるかを選ぶ: **Task の base**（Fleet の Task の既定）/ **HEAD**（まだコミットしていない変更だけ）/ ブランチ（分岐した所から）/ コミット
- 「**空白を無視**」で空白だけの違いを隠す
- 見終わったファイルは見出しの「☐ 見た」で畳んでおける。「開く ↗」でエディタへ
- ファイルが変わると `↻ 新しい変更があります` が出る。押すと読み直す（読んでいる所は動かない）

#### 行にコメントを付けてエージェントへ送る

1. 行にカーソルを乗せると左端に **＋** が出る。押すとその行の下に入力欄が開く（行を押して選び、`c` でも同じ）
   - 複数行は ⇧クリックかドラッグで選んでから ＋ / `c`。↑↓ で行を動かせる
2. コメントを書いて **⌘⏎ で保存**（Esc で取り消し。Enter は改行）
3. 下端の「**注記 N 件**」を押すと一覧が開く。行を押すとその注記へ飛ぶ。編集・解決・削除もここでできる
4. 「**送る ▾**」で送り先のスレッドを選ぶ（Fleet なら Task のスレッド、Editor ならアクティブなスレッドが既定）。
   未送信の注記が**1 通のメッセージ**にまとまって届く。スレッドが作業中なら、終わってから届く
5. 直してもらったら「解決」。まだ直っていないものは「**未解決だけ再送**」でもう一度送れる

注記はアプリを終了しても残る（Fleet は Task ごと、Editor はプロジェクトごと）。

### ターミナル（⌘J）

- 下ドックに開く。上端をドラッグして高さを変える
- `＋` でタブを追加する。タブの名前は、動いているアプリが付けたタイトル（Claude Code なら `✳ Claude Code`）。無ければ「ターミナル 1」
- 出力中の `file:line` はリンクになり、クリックでその行を開く。URL（`http://…`、`localhost:3000` のようなスキーム無しの開発サーバ、アプリが埋め込んだリンク）はクリックでブラウザを開く
- **⌘F** でターミナル内を検索する（scrollback を含む）。⏎ / ⇧⏎ で次 / 前、Aa で大小を区別、`.*` で正規表現、Esc で開いた位置へ戻って閉じる
- **⌘K** で画面と scrollback を消す（いまの行 = プロンプトは残る）。**⌘C / ⌘V / ⌘A** はコピー / 貼り付け / すべて選択
- 右クリックでコピー / 貼り付け / すべて選択 / クリア / 検索のメニューを出す
- **⇧⏎ で改行**できる（Claude Code や Codex の CLI で複数行を打つ時）。⌥ は Meta として働く（⌥B / ⌥F で単語移動など）。ドイツ配列の ⌥L（`@`）や JIS の ⌥¥（`\`）のように記号を打つ組み合わせは、そのまま記号になる
- Finder のファイルやエクスプローラの行をドロップすると、そのパス（空白などは引用して）が入る
- vim / tmux / TUI がマウスを使う時、クリックやホイールはそのアプリへ送られる。**⇧ を押しながら**ドラッグすると、ターミナルの選択になる
- ダブルクリックで語、トリプルクリックで行を選択する
- statusbar のターミナルボタンでも開閉できる
- タブの × は、前面でコマンド（`npm run dev` など）が動いている時だけ「閉じるとこのプロセスも止まります」と確認する（⏎ = 閉じる / Esc = キャンセル）。プロンプト待ちなら確認せずに閉じる。リモート（SSH）と Windows の端末は前面のプロセスを調べられないので確認しない
- `ne terminal …` で外から一覧・読み取り・待機ができる。文字を送るのは設定で許可した時だけ（[§16](#16-コマンドラインne)）
- 文字の大きさ・遡れる行数・カーソルの形は 設定 › 動作とエディタ で変えられる（開いているターミナルにもすぐ効く）。フォントは settings.json の `terminal_font_family` に等幅のフォント名を書く
- 開くシェルを変えたい時は settings.json の `terminal_shell`（と `terminal_shell_args`）に書く（空 = OS の既定）。新しく開くターミナルから効く

## 8. AI エージェント（Agent パネル）

### スレッドを始める

1. **⌘⇧A** で新しいスレッドを作る（右ドックに Agent パネルが開く）
2. 下の composer に依頼を書く
3. **⌘Enter で送信**（Enter は改行。日本語 IME の確定で誤送信しない）

Enter で送信したい場合は、設定 `submit_on_enter` を `true` にする（Shift+Enter が改行になる）。

### レシピ（よく使う依頼をリポジトリに置く）

プロジェクトの `.necoder/recipes/` に Markdown を置くと、composer の行頭で `/` を打った時の候補に `/necoder:<ファイル名>` で出る。選ぶと中身が composer に入る（送られない。確かめて ⌘⏎）。どのエージェントでも使え、リポジトリに commit すればチームで共有できる。

```markdown
# 変更を読んで指摘する
いまのブランチの差分を読み、バグ・抜け・テスト不足を重要な順に挙げて。直すのは指摘の後で。
```

1 行目が `# ` で始まるとそれが候補の説明になり、入る本文からは外れる。

### アカウントを切り替える（Claude Code / Codex）

**設定（⌘,）→ AI エージェント** の Claude Code / Codex の行の下の **アカウント** で選ぶ。

- **＋ 新しいアカウント**: 新しいアカウントを作り、ターミナルで公式のログイン（`claude auth login` / `codex login`）が始まる。ブラウザでログインすれば使える
- **既定** / **account-2** …: 押すと、次に起動するエージェントからそのアカウントになる（動いているスレッドは今のまま）
- **ログイン**: 選んでいるアカウントでもう一度ログインする

アカウントの実体は `<necoder のデータのフォルダ>/accounts/claude/account-2` のようなフォルダで、necoder はエージェントにそのフォルダを使うよう伝えるだけ（`CLAUDE_CONFIG_DIR` / `CODEX_HOME`）。ログインの資格情報は necoder が読まない。名前を変えたい時はフォルダの名前を変える。レート制限の表示もアカウントごとに分かれる。Windows ではまだ使えない。

### 画面の読み方

- **宛先チップ**（composer の上）: `● スレッド名 …… プロジェクト ⎇ ブランチ`。送信前に**誰に・どこへ**送るかを確かめる
- **トークンメーター**: `23.4k/200k` の形で常に表示される
- **transcript**: `⏺ ツール名(引数)` → `⎿ 結果`。長い結果は `▸ N 行` に折り畳まれ、クリックで展開する
- **サブエージェント**: Claude が作業を別のエージェント（Task）に任せると、その手順は Task の行の下に `▸ サブエージェント · N 手順  最新の手順` とまとめて出る（動いている間は最新の手順が変わっていく）。クリックで中の手順を全部見られる
- **✳ Thinking**: 考えている内容。既定で折り畳み、クリックで展開する
- **Todos**: エージェントの実行計画。上部にチェックリストで出る
- **目標**（composer の上の 1 行）: `/goal` でエージェントに目標を渡すと、目的と状態（進行中 / 一時停止 / 達成 など）が出続ける。Codex なら行の右の「一時停止」「再開」「取り消す」で目標を止めたり外したりできる（作業中でも効く）
- 遡って読んでいる間は右下に **↓ 最新へ** ボタンが出る
- 自分の発話が 3 つ以上ある会話では、transcript の右端に**発話ごとの印**が並ぶ（いま読んでいる指示の印だけスレッドの色）。乗せると発話の頭が出て、押すとそこへ飛ぶ

### 操作

| 操作 | 方法 |
|---|---|
| 実行中のターンを止める | composer で **Esc** |
| 承認する | 承認カードの「許可 / 常に許可 / 拒否」 |
| エージェントの質問に答える | composer の上の質問カードで案を押す（案が 1 問だけの質問は押した瞬間に送る。複数選べる質問・問いが複数ある質問は選んでから「これで回答」）。案の下に入力欄があれば**自分で書いて答えられる**: 選ばずに書いて Enter = 書いた文字が答え、案を押す前に書いておくとその案に添えるメモ（複数選べる質問なら選んだ案に足される）。答えたくなければ「答えない」 |
| スレッドの名前を変える | タブをダブルクリック（初回のやり取りの後は自動で名前が付く。エージェントが会話名を送ってくればそれを使う。手で付けた名前は上書きされない） |
| エージェントを決めて新しいスレッドを始める | パレット「AI: 新しいスレッド（Codex）」など（エージェントごとにある）。キーは keymap.json で割り当てる（例: `"cmd-alt-2": "workspace::NewThreadCodex"`）。⌘⇧A は既定のエージェント |
| エージェントのコマンドを使う | composer の先頭で **`/`** を打つ → 候補を ↑↓ で選び **Enter / Tab** で入れる（**esc** で閉じる）。`/compact` などはそのまま送ると効く |
| スレッドを切り替える | ⌃Tab / ⌃⇧Tab、または ⌥⌘← / ⌥⌘→ |
| 過去のスレッドを復元する | **⌘⇧H**（スレッド履歴） |
| スレッドを閉じる | パネル内で ⌘W |
| AI を全画面にする | **⌘⇧⏎**（中央エディタを Agent に差し替える） |
| 過去の時点へ戻す | transcript 内の checkpoint 行をクリック |
| ファイルを渡す | エクスプローラや Finder から composer へドラッグ（@メンションになる） |
| 変更を確認する | ツールカードの `+N −M` から diff タブを開く |

**モデル / 思考量 / 権限モード**は composer 下のピルで選ぶ。選んだ値は次の新規スレッドに引き継がれる。
**エージェント（どの AI か）**は会話を始める前だけ変更できる。別のエージェントを使うときは新しいスレッドを作る。

### 通知

- ターンが終わると右下にトーストが出る（例: 「●rope設計 完了」）。承認待ち・**質問待ち**（エージェントが選択肢付きで聞いてきた時）もトーストと statusbar の待ち表示に出て、押すとそのスレッドへ飛ぶ
- 通知音は猫の声。**完了**は裏のウィンドウのとき、**入力待ち**はそのスレッドが見えていないときだけ鳴る
- 音は設定 `sound_done` / `sound_waiting` で `nyaan` / `nya` / `mew` / `system` / `off` / 任意のファイルから選ぶ
- **作業中はスリープさせない**: エージェントが作業している間は、放っておいてもコンピュータがスリープしない（夜通し走らせても途中で止まらない）。作業中のスレッドが全部終わったら元に戻る。承認待ち・質問待ちの間は止めない。画面は普通に消える。自分で選んだスリープと、ノートの蓋を閉じた時のスリープは止められない。切るには 設定 › 動作とエディタ の「作業中はスリープさせない」を「しない」にする（`keep_awake: "off"`）。mac と Windows だけ
- **通知の履歴（ベル）**: titlebar のベルに、エージェントの完了・失敗・承認待ち・質問待ちが残る（未読があれば件数）。押すと一覧が開き、行を押すとそのスレッドへ飛んで既読になる。右端の ● / ○ で未読に戻せる。残るのはこの窓の最新 100 件で、necoder を終了すると消える。パレット「通知: 履歴を開く」でも開く
- **OS の通知**: その窓を見ていない時（別の窓・別のアプリ・necoder を隠している）は、完了 / 失敗 / 承認待ち / 質問待ちを OS の通知センターにも出す。押すと necoder が前に出てそのスレッドへ飛ぶ。同じスレッドの通知は最新の 1 件に置き換わる。初回に OS の許可を聞かれる。切るには 設定 › 動作とエディタ の「OS の通知」（`system_notifications: false`）
  - `.app` から起動した時だけ出る（開発中の `cargo run` では出ない）
- **Dock のバッジ**（macOS）: 要対応（承認待ち・質問待ちのスレッドと、失敗した Task）の件数を全窓の合計で Dock のアイコンに出す。0 件なら消える。数え方は Fleet ボタンの `◐ N` と同じ
- スレッドのミュート（Fleet サイドバーの 🔕）はトースト・音・OS の通知を止める。ミュートは再起動しても残る

### 終了・窓を閉じる時（動いているものがあれば確認）

エージェントもターミナルも necoder の中で動いているので、necoder を終了すると一緒に止まる。
**⌘Q**（メニュー・Dock の「終了」も同じ）と**窓を閉じる**時に、次のどれかが動いていれば確認が出る（窓を閉じる時は、その窓で動いているものだけを数える。ほかの窓が開いていても確認する）:

- 実行中のエージェント
- 承認・質問を待っているエージェント
- 前面でコマンドが動いているターミナル

| ボタン | 動き |
|---|---|
| **隠して動かし続ける**（既定・⏎） | necoder を隠すだけ。エージェントもターミナルも止まらない。**Dock のアイコン**を押すと戻る（Windows は「最小化して動かし続ける」＝タスクバーから戻る） |
| 終了する（窓を閉じる時は「閉じる」） | そのまま終了する（窓を閉じる時はその窓だけ閉じる）。動いていたものは止まる |
| キャンセル（Esc） | 何もしない |

ほかの窓が開いている状態で 1 つの窓を閉じる時は、「隠して動かし続ける」の代わりに「最小化して動かし続ける」が出て、**その窓だけ**を最小化する。

「動かし続ける」は necoder を**起動したまま**見えなくするだけ。necoder を終了した時・落ちた時は、エージェントもターミナルも止まる（終了しても動き続ける仕組みはまだ無い）。

何も動いていなければ、今までどおり確認なしで終了する。確認が要らなければ 設定 › 動作とエディタ の「終了時の確認」を「しない」にする（`confirm_quit: "never"`）。
ログアウト・再起動・システム終了では確認しない（OS の手続きを止めない）。

窓を全部閉じた後に Dock のアイコンを押すと、最後に閉じた窓が開き直す。

### 使用量・レート制限

- **statusbar の右側**に、いまのスレッドのエージェントのレート制限が `5h 42% · 週 18%` の形で出る（5 時間枠・週枠の使用率）。80% 以上になった窓があると ▲ 付きの警告の色（診断の警告と同じ）になり、Opus の週枠などその他の窓も並ぶ。上限に達して止められている時は ⊗ 付きのエラーの色になる。値をまだ受け取っていなければ何も出ない
- 押すと、エージェントごとの窓・使用率・リセットまでの時間・値を受け取った時刻が出る。コマンドパレット「使用量: レート制限を表示」でも開ける
- **値はエージェントが知らせてきた時にしか変わらない**（出ているのは最後に受け取った値）。Claude Code は claude.ai のサブスクリプションでログインしている時、会話中に使用率が変わると知らせてくる（API キーなどで使っている時は上限の値が無いので出ない）。necoder が Anthropic などへ利用上限を問い合わせることはしない（ログイン情報も読まない）
- **Codex** は会話中に知らせてこないので、このポップオーバーを開いた時だけ Codex CLI（`codex app-server`）に訊く。認証は Codex CLI 自身が行う
- コマンドパレット「使用量: 統計を開く」で、直近 30 日の日付 × エージェントのターン数・トークン・コスト（USD の推定）を表で見られる。数えるのは necoder で使ったターンだけ（ターミナルで直接使った Claude Code などは含まない）。Codex はコストを報告しないので `—`

### Todo ボード

コマンドパレット「表示: Todo ボード」、またはレールの Todo アイコン。`.necoder/todos.md` を板として表示する。

- ✨ 今日の計画: ROADMAP と `git status` からタスクの下書きを作る
- タスクをスレッドへ送ると、完了時にエージェントが自分でチェックを付ける

### MCP サーバ

**設定 → MCP サーバ** で、エージェントに持たせる道具（MCP サーバ）を有効化する。
`~/.codex/config.toml` / `~/.claude.json` / `~/.cursor/mcp.json` にあるサーバは自動で一覧に載る（既定は無効）。

### Skills（エージェントに necoder の使い方を渡す）

Claude Code や Codex は、skill の置き場にある `SKILL.md`（手順書）を読んで動き方を変える。
necoder の skill を入れておくと、エージェントが `ne fleet …` などの necoder のコマンドを、入っている necoder の版に合わせて使えるようになる。

- **設定（⌘,）→ AI エージェント → Skills** の「necoder の skill」で **入れる**。necoder が前に置いた古い版があると「更新があります」と出るので **更新する**
- 置くのは入口だけ（`~/.claude/skills/necoder/SKILL.md`・`~/.codex/skills/necoder/SKILL.md`）。使い方の本文は、エージェントが `ne skills get` を実行して、動いている necoder から読む。necoder を更新しても置き直す必要はない
- 同じ節に、見つかった skill の一覧（名前・説明・場所・どのエージェントが読むか）が出る。front matter が壊れているものは一覧から外し、件数だけを出す
- 人や別のツールが書いた `necoder/SKILL.md` は、設定画面からは上書きしない

ターミナルからも同じことができる:

| コマンド | 動作 |
|---|---|
| `ne skills get [--full]` | エージェント向けの使い方（この版の necoder に合ったもの）を出す。`--full` は全コマンドの詳細つき |
| `ne skills install [--agent claude\|codex\|all] [--project <dir>] [--force]` | 入口の SKILL.md を置く。`--agent` を省くと `~/.claude` / `~/.codex` があるエージェントへ（どちらも無ければ Claude Code）。`--project` はそのプロジェクトの `.claude/skills`（Codex は `.agents/skills`）へ。中身の違うファイルがあると知らせて止まり（終了コード 1）、`--force` で上書きする |
| `ne skills list [--project <dir>]` | `~/.claude/skills`・`~/.codex/skills`・`~/.agents/skills` と、プロジェクト（省くと今いるフォルダ）の `.claude/skills`・`.agents/skills` の skill を一覧する |

## 9. Fleet モード（複数エージェントの並走）

1 つのリポジトリで、複数のエージェントに別々の worktree で並行作業させるモード。

### 入り方

**⌘⇧M**、titlebar の `Editor | Fleet | Chat` の Fleet、またはレールの Fleet アイコン。
要対応（承認待ち・質問待ちのスレッドと、失敗した Task）があると Fleet ボタンに `◐ 2` のような件数が出る（macOS では Dock のアイコンにも全窓の合計が出る）。

### 画面

```text
レール | Fleet サイドバー          | 系譜の帯（ブランチの分岐と統合）
      |  ⚑ Captain              |  舞台: Task カード 1〜3 枚
      |  要対応（裁くもの）       |   ┌ ● 名前 ⎇ branch [状態] …… [次へ] ⤢ ⋯
      |  ⌂ main（統合先）        |   │ スレッド | 変更（変更レビュー）| ターミナル | ファイル | ＋▾
      |  Task 行 …              |   └ composer
      |  ＋ Task（⌘N）           |  下段: ニュース / ターミナル
```

Task をいつも同じブランチから切りたい（`main` ではなく `develop` から等）時は、リポジトリの `.necoder/settings.json` に `"task_base": "origin/develop"` のように書く。＋ Task の「詳細」で起点を空のままにすると、そこから切る（CLI の `ne fleet create` も同じ）。

Task が 6 本以上あると、サイドバーの ⌂ main の下に **絞り込み欄**が出る。名前・ブランチ・頼んだこと・いま何をしているかのどれかに含まれる語で Task を絞れる（空白で区切ると全部の語を含む Task だけ）。欄の右の「並び: レール」を押すと、最近頼んだ順・要対応（承認や質問を待っているもの）が先の順に切り替わる。

### 基本の流れ

1. **⌘N（＋ Task）** で依頼を 1 つ書く → **⌘⏎**
   - `task/<名前>` ブランチと worktree が作られ、エージェントが作業を始める
   - 作っている間はサイドバーに「worktree を作っています…」「準備スクリプトを流しています…」の行が出る。`×` で取り消せる
     （作り終えた分は消える）。作れなかった時は理由と **やり直す** が残る
2. サイドバーで状態を見る。**要対応**に出たものだけ対処する（許可 / 確認 / 修正の指示）
3. Task カードの **次へ** を押して進める（稼働中 → レビューへ → Integrate → 片付け）
4. **Integrate（main への統合）は必ず人間が押す**

**同じ依頼を複数のエージェントで比べる**: ＋ Task の「詳細」の「並べて比べる」でエージェントを選ぶ（複数可・「各 1 / 2 / 3」で 1 体あたりの本数）。選んだエージェントごとに Task（`task/<名前>-codex` のように末尾にエージェント名）が切られ、Task 名に `· Codex` のような印が付く。Fleet の舞台に横に並ぶので、各カードの「変更」で結果を見比べる（一度に 6 本まで）。

Task の変更から開く diff は、Task を切った時点の commit（base）と作業ツリーを比べる。題名は `<名前> ⇄ <base の短い SHA>` になり、エージェントがコミット済みの変更も出る。

### 主なキー

| キー | 動作 |
|---|---|
| ⌘⇧M | Editor ⇄ Fleet |
| ⌘N | ＋ Task |
| ⌘0 | Captain へ |
| ⌘⇧U | 次の要対応へ |
| ⌘⇧1 / 2 / 3 | 舞台に 1 / 2 / 3 枚並べる（◫ でピン留めした Task を並べる） |
| ⌘⇧G | 系譜の帯を畳む / 展開 |

### Captain（任意）

Captain は、目標を Task に分解して起動・レビューまで采配するスレッド。コードは書かず、Integrate もしない。
任命するには **設定（⌘,）→ AI エージェント** で、使いたいエージェントの行の **Captain にする** を押す。
任命中の行は `⚑ Captain` と表示され、もう一度押すと解任する。Fleet サイドバーの「Captain を任命する」を押してもこのページが開く。
未任命でも Fleet は使える（settings.json の `captain_agent` に直接書いても同じ）。

このボタンが更新するのはユーザー設定。プロジェクトの `.necoder/settings.json` に `captain_agent` がある場合はそちらが優先されるため、その設定を編集・削除して変更する。

### まとめて片付ける

パレットの「Task: 片付け…」で、いまのリポジトリの Task が並ぶ。各 Task に、worktree を消したら失うもの（未コミットの変更・main に無いコミット）と、worktree の大きさ（ディスク上・失うものを数え終えてから測る）が出る。「並び: 作った順」を押すと大きい順に並ぶ（場所を空けたい時に大きいものから選べる）。

- **統合済み・終了済みを選ぶ** → **終了する**: Task の一覧から外す（worktree はディスクに残る）
- **worktree を削除**: 選んだうち**失うものが無い Task だけ**を消す（ブランチは残る）。消す直前にもう一度確かめ、その間に変更が出ていたら消さない
- 失うものがある Task は、Task カードの ⋯ から 1 本ずつ消す（何を失うかを見せて確認する）

### Task の片付け（⋯ メニュー）

下の段ほど残るものが減る。

| 操作 | 残るもの |
|---|---|
| カードを閉じる | Task・worktree・動いているエージェント |
| エージェントを止める | Task・worktree |
| 休ませる（静かなエージェントがある時） | Task・worktree・会話（次に送ると続きから・メモリだけ空く） |
| Task を終了 | worktree（ディスク上） |
| worktree を削除 | ブランチ |
| ブランチごと削除 | なし |

削除の前に、失う未コミットの変更と未統合のコミットの数が表示される。

### 準備スクリプト

`.necoder/worktree-setup.sh` を置くと、worktree 作成直後に 1 回実行される。`.env` のコピーや依存のインストールに使う。
＋ Task ダイアログの「作る」でテンプレートが書き出される。急ぐ時は ＋ Task の「詳細」で「今回は準備スクリプトを実行しない」を選べる。

準備スクリプトが失敗すると、その Task は「失敗」になり、頼んだ内容はまだエージェントに送られない。Fleet の要対応に出る
失敗のカードで **「準備をやり直す」**（スクリプトを直してから押す・通れば頼んだ内容を送る）か **「準備を飛ばして始める」** を選ぶ。

### `.worktreeinclude`（無視しているファイルを Task へ持ち込む）

リポジトリのルートに `.worktreeinclude` を置き、`.gitignore` と同じ書き方で持ち込みたいファイルを書くと、新しい Task の
worktree へ写される（準備スクリプトより前）。写るのは **git が無視しているファイルだけ**（`.env`・`secrets/*` など）。

```
.env
.env.local
config/local.json
```

既にあるファイルは上書きしない。500 件・64 MiB までで、`node_modules` のような大きな物は準備スクリプトで用意する。

## 10. Chat モード（プロジェクトに紐づかない会話）

claude.ai のように、特定のプロジェクトに属さない相談や資料づくりをする場所。

### 使い方

1. **⌘⇧J**（または titlebar の Chat）で入る。窓の縁が無彩色になる = プロジェクトの外にいる
2. **⌘N** で新しいチャット
3. ファイルや画像を composer へドラッグ / 貼り付けして渡せる
4. エージェントが作った HTML / Markdown は、右側にプレビューで自動表示される

### ファイルの置き場所と権限

- 会話ごとのフォルダ: `~/Documents/necoder/<日付 最初の文>/`。成果物はその中の `artifacts/`
- necoder を消してもファイルは残る。置き場は設定で変えられる
- エージェントが書けるのは **そのチャットのフォルダと、渡したファイルだけ**。渡したファイルへの書き込みは最初の 1 回だけ確認される

### 一覧の操作

- 検索欄: タイトルと本文を検索
- 右クリック: ピン留め / フォルダを表示 / 会話を Markdown で書き出す / 削除
- 削除のとき、フォルダのファイルは既定で**残す**（消す場合も OS のゴミ箱へ移す）

使っていないチャットのエージェントは一定時間（既定 10 分）で自動停止し、次の送信で会話を引き継いで再開する。

## 11. Remote SSH

リモートマシン上のプロジェクトを、ローカルと同じ操作で編集する。

1. レールの **＋ → SSH**（またはレールの SSH アイコン）でホストを選ぶ
   - コマンドラインからは `necoder 'ssh://user@example.com:22/home/user/project'`
2. システムの OpenSSH 設定（`~/.ssh/config`・鍵・ssh-agent・ProxyJump）がそのまま使われる
3. 必要なサーバは自動で配備される（チェックサム検証つき）

- リモートのプロジェクトはレールのアイコン右下に server バッジが付く
- statusbar の **SSH** チップが接続状態を表す（緑 = 接続済み / 黄 = 接続中 / 赤 = 切断）。「再接続」で即座に張り直せる
- リモートの統合ターミナルで `ne .` を実行すると、そのディレクトリを接続元のウィンドウで開く

### スマホから見る（リモート管制）

**設定 → スマホ連携 → 接続用QRを発行** で、スマホの PWA とペアリングできる。QR は 5 分有効。
詳細は [`REMOTE-CONTROL.md`](./REMOTE-CONTROL.md)。

> 社外サービス（リレー）を経由する機能。業務プロジェクトで使う前に、所属組織の情報セキュリティ規程で可否を確認すること。

## 12. Windows でのキーの違い

基本は `⌘` → `Ctrl`。VSCode の作法に合わせて、次のキーが変わる。

| 動作 | macOS | Windows |
|---|---|---|
| 単語単位の移動 / 選択 / 削除 | ⌥← ⌥→ / ⇧⌥← / ⌥⌫ | Ctrl+← → / Ctrl+Shift+← / Ctrl+Backspace |
| 文書の先頭 / 末尾 | ⌘↑ / ⌘↓ | Ctrl+Home / Ctrl+End |
| 置換 | ⌥⌘F | Ctrl+H |
| カーソルを追加 | ⌥⌘↑ / ⌥⌘↓ | Ctrl+Alt+↑ / ↓ |
| 前後のプロジェクト | ⌃⌘↑ / ⌃⌘↓ | Ctrl+Alt+Shift+↑ / ↓ |
| 系譜の帯（Fleet） | ⌘⇧G | Ctrl+Alt+G |
| やり直し | ⌘⇧Z | Ctrl+Shift+Z または Ctrl+Y |
| 終了 | ⌘Q | Alt+F4 |
| ターミナル内のコピー / 貼り付け / すべて選択 | ⌘C / ⌘V / ⌘A | Ctrl+Shift+C / V / A |
| ターミナル内の検索 / クリア | ⌘F / ⌘K | Ctrl+Shift+F / K |

emacs 風の ⌃ キーはエディタでは使えない（矢印キーで代用）。ターミナルの中では Ctrl + 文字（Ctrl+C・Ctrl+F・Ctrl+W・Ctrl+P・Ctrl+J など）はそのままシェルやアプリへ届く。そのため、ターミナルにフォーカスがある間は Ctrl+P（ファイルファインダ）や Ctrl+J（ターミナルの開閉）などは効かない（ターミナルの外をクリックしてから使う）。

## 13. 設定・テーマ・色

### 設定画面（⌘,）

左のナビでページを選ぶ: **AI エージェント / MCP サーバ / 外観 / リモート / 動作とエディタ**。
探したい設定があれば、ナビの上の**検索欄**に打つ（例: `自動保存`・`通知`・`font_size`）。一致した設定が全ページから集まり、その場で切り替えられる。ページ名を押すとそのページが開く。
ファイルで編集したいときは、コマンドパレット「設定: settings.json を開く」。

| 置き場所 | 効く範囲 |
|---|---|
| アプリの `settings.json`（macOS: `~/Library/Application Support/necoder/`） | 全体 |
| プロジェクトの `.necoder/settings.json` | そのプロジェクトだけ（`color` / `icon` / `task_base` など） |

よく使う設定:

| キー | 既定 | 意味 |
|---|---|---|
| `theme` | `necoder-dark` | テーマ名 |
| `font_size` / `tab_size` | `13` / `4` | 文字サイズ / タブ幅 |
| `density` | compact | 行の密度（compact / cozy）。**未実装**: 値は読むが、まだ画面に反映されない |
| `soft_wrap` | `false` | 折り返し表示 |
| `format_on_save` | `false` | 保存時にフォーマット |
| `preview_tabs` | `true` | エクスプローラの 1 回クリックでプレビュータブ（次の 1 回クリックで置き換わる）に開く |
| `auto_save` | `off` | 自動保存（`focus_change` = 他へ移った時 / `after_delay` = 手を止めた時も） |
| `locale` | OS に従う | UI の言語（日本語 / 英語）。設定 › 外観 の「表示言語」でも変えられ、その場で切り替わる（macOS のメニューバーは次の起動から） |
| `submit_on_enter` | `false` | Enter で送信するか |
| `sound_done` / `sound_waiting` | `nyaan` | 完了 / 入力待ちの通知音 |
| `sound_volume` | `100` | 通知音の大きさ（%・0 で鳴らさない・mac） |
| `system_notifications` | `true` | 見ていない窓のエージェントの完了・失敗・承認待ち・質問待ちを OS の通知センターにも出す |
| `confirm_quit` | `running` | ⌘Q・窓を閉じる時、動いているものがあれば確認する（`never` = しない） |
| `keep_awake` | `working` | エージェントが作業している間はスリープさせない（`off` = しない・mac と Windows） |
| `terminal_font_size` | `12.5` | ターミナルの文字の大きさ（8〜32） |
| `terminal_font_family` | 空 | ターミナルのフォント（空 = エディタと同じコードフォント。等幅のフォント名を書く） |
| `terminal_scrollback` | `10000` | ターミナルで遡れる行数（上限 100000・減らすと古い行から捨てる） |
| `terminal_cursor` | `block` | ターミナルのカーソルの形（`bar` = 縦線 / `underline` = 下線。vim などの指定が優先） |
| `terminal_shell` | 空 | 手元のターミナルで開くシェル（空 = OS の既定。名前か絶対パス。例 `"fish"`・Windows なら `"bash"`（Git Bash）や `"wsl"`）。新しく開くターミナルから効き、SSH 先は接続先のシェルのまま |
| `terminal_shell_args` | `[]` | 上のシェルに渡す引数（例 `["-l"]`） |
| `reduce_motion` | `false` | スピナー等の動きを止める |
| `captain_agent` | なし | Fleet の Captain に使うエージェント（設定 → AI エージェントで選べる） |

設定画面のトグルは settings.json へ書き込む。settings.json を手で編集していて JSON として読めない状態（末尾のカンマ・コメントなど）のときは、ファイルを上書きせず「settings.json を読めないので保存しませんでした」と理由つきで知らせる。直してから押し直す。

### テーマ

- **⌘K ⌘T** でテーマ選択（選んでいる間はライブプレビュー）
- 同梱: necoder Dark / Light・Solarized Dark / Light・Gruvbox Dark・Catppuccin Mocha・High Contrast Dark
- 自作テーマ: 色トークンを上書きする JSON を `~/Library/Application Support/necoder/themes/*.json` に置く

テーマ（画面の配色）とプロジェクト色（識別）は別の設定で、どのテーマでもプロジェクト色は同じ場所に出る。

## 16. コマンドライン（`ne`）

`ne` は necoder の CLI（入れ方は [§1](#ターミナルから開くne-コマンド)）。`ne fleet …` などは `necoder fleet …` と同じで、
`ne` が無い環境では necoder の実体（macOS: `/Applications/necoder.app/Contents/MacOS/necoder`）を直接呼ぶ。
失敗すると理由を標準エラーに出し、終了コード 1 を返す。エージェント向けの全コマンドの説明は `ne skills get --full` が、入っている版の実装から出す。

### 開く

| コマンド | 動作 |
|---|---|
| `ne <パス>` | 起動中の necoder で開く（フォルダはレールへ・ファイルはタブへ）。引数なしは前面に出すだけ |
| `ne <ファイル>:<行>[:<列>]` | そのファイルを開いて行（と列）へ飛ぶ。`:12` を含む名前のファイルが本当にあればそちらを開く。necoder が起動していない時はファイルを開くだけ |
| `ne --diff <左> <右>` | 2 つのファイルの差分を、読み取り専用の diff タブで開く（necoder の起動が必要） |

### Fleet（`ne fleet …`）

| コマンド | 動作 |
|---|---|
| `ne fleet create [root] [名前]` | Task を切る（`task/*` ブランチと worktree を作り、台帳に登録） |
| `ne fleet list [root]` | このリポジトリの Task の一覧（JSON） |
| `ne fleet status <task> <phase> [要約]` | phase を進めて要約を残す |
| `ne fleet wait <task> <phase\|activity> [秒]` | 指定の phase / 動きになるまで待つ |
| `ne fleet depend <task> <依存...>` / `wait-deps <task> <phase> [秒]` | 依存の宣言と待ち |
| `ne fleet review <task> [統合先]` | Conflict Radar（統合先を変えない merge の試算） |
| `ne fleet spawn-agent <task> [agent] [prompt...]` / `send <task> <文...>` | エージェントを起こす / 追撃する（necoder の起動が必要） |
| `ne fleet digest <task>` / `events [id]` | 今の要約 / 台帳のイベント |

`ne fleet integrate` もあるが、**Integrate は人間が押す操作**（Captain やエージェントには使わせない）。

**`<task>` の指し方**: id のほか、`branch:task/fix-login`（`task/` は省ける）・`name:Fix login`（Task の名前と完全一致）・
`active`（necoder で選択中の Task）。前置きなしは id → ブランチ → 名前の順に探す。ブランチと名前は今いるフォルダの
リポジトリの Task だけから探し、1 つに絞れなければ候補を出して止まる。統合先（main）は id でしか選べない。

### 端末（`ne terminal …`）

起動中の necoder の端末（下ドックのタブと、Fleet の Task カードに置いた端末）を外から扱う。

| コマンド | 動作 |
|---|---|
| `ne terminal list [task]` | 端末の一覧（ハンドル・どの Task か・下ドックか Task カードか・出力が止まってからの時間） |
| `ne terminal read <端末> [scrollback の行数]` | 今の画面の文字（と、その上の scrollback）を出す |
| `ne terminal send <端末> [--enter] <文字...>` | 文字を送る。`--enter` で最後に Enter |
| `ne terminal wait <端末> [止まる秒数] [期限の秒数]` | 出力が指定の秒数（既定 2）止まるまで待つ（既定 600 秒で失敗） |

- `<端末>` は `list` が返すハンドル（`t` + 番号）か `active`（選択中のプロジェクトの下ドックで前に出ている端末）。ハンドルは necoder を再起動すると変わる
- **`send` は既定で効かない。** 送った文字はその端末でそのまま実行されるので、**設定 → 動作とエディタ →「CLI から端末へ入力を送る」**を on にした時だけ受け付ける（`ne config set allow_terminal_send true` でも同じ）。一覧・読み取り・待機は off のままでも使える
