# necoder ユーザーマニュアル

necoder（ねこーだー）の使い方をまとめた利用者向けの手引き。
キーは macOS 表記で書く。Windows では `⌘` を `Ctrl` に読み替える（例外は [§12](#12-windows-でのキーの違い)）。

> この文書は 2026-09-23 時点の実装（v0.1.19）に合わせている。キーの正は既定 keymap（`crates/keymap_core`）で、
> アプリ内の **⌘K ⌘S（ショートカット一覧）** が常に最新を表示する。食い違ったらそちらを信じる。

## 1. インストールと初回起動

### macOS 13 以降（Apple Silicon）

1. [Releases](https://github.com/iKora128/necoder/releases) から `necoder.dmg` を取得する
2. **necoder** を「アプリケーション」へドラッグする
3. 起動する。署名・公証済みで、以後の更新はアプリ内で行われる（適用前に Apple 署名を検証する）

### Windows 10 以降（x64）

1. Releases から `necoder-windows-x64.zip` を取得して展開する
2. `necoder.exe` を実行する。新版が出るとアプリ内で通知され、リリースページを開ける

### AI 機能を使う準備

AI 機能は [`claude` CLI](https://docs.anthropic.com/en/docs/claude-code)（Claude Code）を経由して動く。
CLI をインストールしてログインしておけば、**API キーは不要**（既存の Claude Code の契約をそのまま使う）。
初回起動時の「ようこそ」画面にエージェントの一覧と導入状況が出るので、そこから始められる。

### ターミナルから開く（`ne` コマンド）

1. **設定（⌘,）→ AI エージェント → コマンドライン** で `ne` をインストールする（macOS の認証を許可）
2. ターミナルで `ne .` を実行する

necoder が起動中ならそのウィンドウで開き、起動していなければアプリを起動する。

## 2. 画面の見かた

```text
┌ titlebar: ● プロジェクト ⎇ branch ▾ | Editor | Fleet | Chat |     実行中スレッド   [ドック開閉] ┐
│レール│ 左ドック（エクスプローラ等）│ タブ / エディタ               │ 右ドック（Agent パネル） │
│ ●    │                          │                               │                        │
│ ●    │                          ├ 下ドック（ターミナル）         │                        │
└ statusbar: ⎇ branch · 診断 · ターミナル · 実行状況のまとめ · 更新 · 行:列 · 言語 ─────────┘
```

### 色の意味（これだけ覚えればよい）

necoder は色を**識別のためだけ**に使う。装飾には使わない。

| 色 | 何を表すか | どこに出るか |
|---|---|---|
| **プロジェクト色** | 今どのプロジェクトにいるか | 窓の縁・レールの枠・アクティブタブの上線・キャレット・選択の左バー |
| **スレッド色** | どの AI スレッドと話しているか | スレッドタブ・宛先チップ・composer の枠・送信ボタン・トークンメーター |

エージェントの状態は**色ではなく形と動き**で表す。

| 形 | 状態 |
|---|---|
| ⠋⠙⠹（回る点字） | 作業中 |
| ◐ 半円・速い脈動 | 承認待ち（あなたの操作が必要） |
| ✓ リング・静止 | 完了・未確認 |
| ○ 淡い点 | 待機 |

### 主な領域

- **レール**（左端の縦列）: 開いているプロジェクト。下部にエクスプローラ / 検索 / Git / Todo / AI / ターミナル / SSH のアイコン
- **titlebar のピル**: 名前をクリック = プロジェクト切替（⌘O）、`⎇ branch ▾` = ブランチ / worktree メニュー
- **statusbar 中央**: 全プロジェクトの「N 実行 · M 承認待ち · K 完了」。クリックで該当スレッドへ飛ぶ

## 3. プロジェクトを開く・切り替える

| やりたいこと | 操作 |
|---|---|
| フォルダ・ファイル・リモートを開く | レールの **＋**（最近開いたものも一覧に出る） |
| 開いているプロジェクト間を移動 | **⌘O**（プロジェクトとブランチ / worktree の 2 階層一覧） |
| n 番目のプロジェクトへ | **⌘1〜⌘9** |
| 前後のプロジェクトへ | **⌃⌘↑ / ⌃⌘↓** |
| 連続で流し見する | レールを 1 回クリック → **↑ / ↓**（Esc で作業面に戻る） |
| 新しいウィンドウで開く | ⌘O 内で **⌘⏎** / **⌘⇧N** |
| ブランチを別フォルダで並行作業 | ピルの `⎇ ▾` →「＋ ブランチを worktree で開く」 |

キー操作で切り替えると、画面中央に行き先の「プロジェクト名 ⎇ ブランチ」が約 1 秒表示される。

**レールの右クリック**: 色の変更 / 新しいウィンドウで開く / レールから外す /（worktree のみ）worktree を削除。

### プロジェクトのアイコンと色

- `.necoder/icon.png`（jpg / webp も可）を置くと、レールのアイコンになる
- 色は自動で割り当てられる。変えるには **⌘K ⌘C** またはレールの右クリック。任意の hex も入力できる
- 色はプロジェクトに付く。レールの並び順・ウィンドウ・再起動では変わらない

## 4. ファイルを編集する

### ファイルを開く

- **⌘P**: ファイルファインダ（あいまい検索）
- **⌘⇧P**: コマンドパレット（全コマンドを名前で実行）
- エクスプローラ（左ドック）: ツリー / カラム / アイコンの 3 表示をフッタで切り替える

**エクスプローラの操作**

- 右クリック: 開く / ここをプロジェクトとして開く / 分割して開く / Finder に表示 / パスをコピー（⌥⌘C）/ 名前を変更（⏎）/ ゴミ箱に入れる（⌘⌫）
- ドラッグ: エクスプローラ内の移動は **移動**、Finder からのドラッグは **コピー**。同名ファイルは上書きしない
- ファイル操作（作成・名前変更・移動・複製・削除）は ⌘Z では取り消せない。削除は OS のゴミ箱へ移すだけなので、戻すときはゴミ箱から出す
- 右上の ↻: 外部（エージェント等）が作ったファイルが見えないときに読み直す

### 編集の基本

| キー | 動作 |
|---|---|
| ⌘S | 保存 |
| ⌘Z / ⌘⇧Z | 元に戻す / やり直し |
| ⌘D | 同じ語を次も選択（マルチカーソル） |
| ⌥⌘↑ / ⌥⌘↓ | 上 / 下にカーソルを追加 |
| ⌥↑ / ⌥↓ | 行を上 / 下へ移動 |
| ⇧⌥↑ / ⇧⌥↓ | 行を上 / 下へ複製 |
| ⌘⇧K | 行を削除 |
| ⌘/ | コメント切替 |
| ⌘] / ⌘[ | インデント / 逆インデント |
| ⌥Z | 折り返し表示の切替 |
| ⌃G | 行番号へ移動 |
| ⌃- / ⌃⇧- | 移動履歴を戻る / 進む |
| ⌘\ | 右に分割 |
| ⌘W / ⌘⇧T | タブを閉じる / 閉じたタブを復元 |
| ⌘} / ⌘{ | 次 / 前のタブ |

emacs 風の移動（⌃A ⌃E ⌃N ⌃P ⌃F ⌃B ⌃K など macOS 標準のもの）も使える。

### プレビュー

`.md` と `.html` は **⌘⇧V** でソースと表示を切り替えられる。HTML は OS 標準の WebView（macOS は WKWebView、Windows は WebView2）で表示する。

Markdown のプレビューのリンクは押せる。URL はブラウザ（localhost なら下の Web タブ）で、ファイルへのリンクはタブで開く。

### 開発サーバを見る（Web タブ）

`npm run dev` などで立てた開発サーバは、エディタのタブで見られる。

- **⌘⇧P →「プレビュー: localhost を開く…」** でポート番号（`5173`）か localhost の URL（`localhost:3000/app`）を入れる
- エージェントの会話や Markdown に出てきた `http://localhost:…` のリンクを押しても開く
- ツールバー: 戻る / 進む / 再読み込み / ズーム（− 100% +）/ 幅（全幅・375・768・1280）/ DevTools / 既定のブラウザで開く
- 開けるのはこのマシンの `localhost` / `127.0.0.1` / `[::1]` だけ。ページの中で外部のサイトへ移動しようとした時や、新しい窓を開こうとした時は、既定のブラウザで開く
- 開いていた Web タブは再起動しても戻る。サーバが起動していない時は「接続できませんでした」と出るので、起動してから再読み込みする

#### 画面の要素を AI に見せる（Design モード）

「このボタンをもう少し小さく」のように、見えている要素を指して頼める。

1. Web タブのツールバーの **Design**（または **⌘⇧D**）を押す
2. ページの上でマウスを動かすと、下の要素に枠と名前が出る。**クリック**で選ぶ（**Shift+クリック**なら続けて何個でも選べる）
3. 選んだ要素は、アクティブなスレッドの入力欄に「◎ 要素の名前」の画像チップと説明の文章として入る。**送信はされない**ので、指示を書き足して ⌘Enter で送る

- 説明には、セレクタ・位置と大きさ・主なスタイル・テキスト・HTML の抜粋と、React なら部品の名前とソースの場所（開発ビルドの時）が入る
- パスワード欄の値や、トークン・API キーらしい属性は伏せて入る。URL の `?` 以降も落とす
- Esc かもう一度 Design を押すと終わる

### AI インライン編集（⌘I）

1. コードを選択して **⌘I**
2. 指示を入力して Enter
3. 差分を見て **⏎ で適用 / Esc で破棄**

ターミナルで ⌘I を押すと、指示からコマンドを生成する。

### 未保存のまま終了しても消えない（hot exit）

未保存の変更を残して終了しても、次回起動時に「前回終了時の未保存の変更があります」と出て **復元** できる。

## 7. Git とターミナル

### Git（ソース管理パネル・⌃⇧G）

- エクスプローラとガター（行番号の横）に変更が色で出る
- **F7 / ⇧F7**: 次 / 前の変更箇所（hunk）へ。hunk 単位でステージ・取り消しができる
- パネルの変更の行を押すと、そのファイルの diff をタブ（`<名前> ⇄ HEAD`）で開く。行の右の ＋ / − はステージ / 解除
- パネルでステージ → メッセージ入力 → **⌘⏎ でコミット**。メッセージ欄は Enter で改行、⌘V・⌘Z・日本語入力が効く。メッセージは AI に生成させることもできる
- コミットと push では、その repo のフック（pre-commit・commit-msg・pre-push）が走る
- コミット・push・pull・PR などが失敗すると、理由（git / gh の出力の要点）がトーストに出る。フックの出力のように長いときは、トーストを押すと全文をタブで開ける
- ブランチの作成・削除、worktree でレールに開く、GitHub で PR を作成（`gh` が必要）
- blame、diff タブにも対応。差分が無いときは diff タブを開かずトーストで知らせる。削除されたファイルは題名に「削除」と出る

### 変更レビュー

変更したファイルを全部 1 画面で読む。パレット「**Git: 変更をレビュー**」か、ソース管理パネルの「**⇄ 変更をレビュー**」でタブとして開く。
Fleet では Task カードの「**変更**」タブが同じ画面になる。

- 左のツリーでファイルを押すと、その位置へ飛ぶ。`☰` でツリーを隠せる
- 追加した行は緑、消した行は赤の薄い面。左の 2 列が旧・新の行番号
- 変更の無い所は `⋯ N 行` に畳まれている。押すと前後 20 行ずつ開く
- 「**比較**」で何と比べるかを選ぶ: **Task の base**（Fleet の Task の既定）/ **HEAD**（まだコミットしていない変更だけ）/ ブランチ（分岐した所から）/ コミット
- 「**空白を無視**」で空白だけの違いを隠す
- 見終わったファイルは見出しの「☐ 見た」で畳んでおける。「開く ↗」でエディタへ
- ファイルが変わると `↻ 新しい変更があります` が出る。押すと読み直す（読んでいる所は動かない）

#### 行にコメントを付けてエージェントへ送る

1. 行にカーソルを乗せると左端に **＋** が出る。押すとその行の下に入力欄が開く（行を押して選び、`c` でも同じ）
   - 複数行は ⇧クリックかドラッグで選んでから ＋ / `c`。↑↓ で行を動かせる
2. コメントを書いて **⌘⏎ で保存**（Esc で取り消し。Enter は改行）
3. 下端の「**注記 N 件**」を押すと一覧が開く。行を押すとその注記へ飛ぶ。編集・解決・削除もここでできる
4. 「**送る ▾**」で送り先のスレッドを選ぶ（Fleet なら Task のスレッド、Editor ならアクティブなスレッドが既定）。
   未送信の注記が**1 通のメッセージ**にまとまって届く。スレッドが作業中なら、終わってから届く
5. 直してもらったら「解決」。まだ直っていないものは「**未解決だけ再送**」でもう一度送れる

注記はアプリを終了しても残る（Fleet は Task ごと、Editor はプロジェクトごと）。

### ターミナル（⌘J）

- 下ドックに開く。上端をドラッグして高さを変える
- `＋` でタブを追加する。タブの名前は、動いているアプリが付けたタイトル（Claude Code なら `✳ Claude Code`）。無ければ「ターミナル 1」
- 出力中の `file:line` はリンクになり、クリックでその行を開く。URL（`http://…`、`localhost:3000` のようなスキーム無しの開発サーバ、アプリが埋め込んだリンク）はクリックでブラウザを開く
- **⌘F** でターミナル内を検索する（scrollback を含む）。⏎ / ⇧⏎ で次 / 前、Aa で大小を区別、`.*` で正規表現、Esc で開いた位置へ戻って閉じる
- **⌘K** で画面と scrollback を消す（いまの行 = プロンプトは残る）。**⌘C / ⌘V / ⌘A** はコピー / 貼り付け / すべて選択
- 右クリックでコピー / 貼り付け / すべて選択 / クリア / 検索のメニューを出す
- **⇧⏎ で改行**できる（Claude Code や Codex の CLI で複数行を打つ時）。⌥ は Meta として働く（⌥B / ⌥F で単語移動など）。ドイツ配列の ⌥L（`@`）や JIS の ⌥¥（`\`）のように記号を打つ組み合わせは、そのまま記号になる
- Finder のファイルやエクスプローラの行をドロップすると、そのパス（空白などは引用して）が入る
- vim / tmux / TUI がマウスを使う時、クリックやホイールはそのアプリへ送られる。**⇧ を押しながら**ドラッグすると、ターミナルの選択になる
- ダブルクリックで語、トリプルクリックで行を選択する
- statusbar のターミナルボタンでも開閉できる

## 8. AI エージェント（Agent パネル）

### スレッドを始める

1. **⌘⇧A** で新しいスレッドを作る（右ドックに Agent パネルが開く）
2. 下の composer に依頼を書く
3. **⌘Enter で送信**（Enter は改行。日本語 IME の確定で誤送信しない）

Enter で送信したい場合は、設定 `submit_on_enter` を `true` にする（Shift+Enter が改行になる）。

### 画面の読み方

- **宛先チップ**（composer の上）: `● スレッド名 …… プロジェクト ⎇ ブランチ`。送信前に**誰に・どこへ**送るかを確かめる
- **トークンメーター**: `23.4k/200k` の形で常に表示される
- **transcript**: `⏺ ツール名(引数)` → `⎿ 結果`。長い結果は `▸ N 行` に折り畳まれ、クリックで展開する
- **✳ Thinking**: 考えている内容。既定で折り畳み、クリックで展開する
- **Todos**: エージェントの実行計画。上部にチェックリストで出る
- **目標**（composer の上の 1 行）: `/goal` でエージェントに目標を渡すと、目的と状態（進行中 / 一時停止 / 達成 など）が出続ける
- 遡って読んでいる間は右下に **↓ 最新へ** ボタンが出る

### 操作

| 操作 | 方法 |
|---|---|
| 実行中のターンを止める | composer で **Esc** |
| 承認する | 承認カードの「許可 / 常に許可 / 拒否」 |
| スレッドの名前を変える | タブをダブルクリック（初回のやり取りの後は自動で名前が付く。エージェントが会話名を送ってくればそれを使う。手で付けた名前は上書きされない） |
| エージェントのコマンドを使う | composer の先頭で **`/`** を打つ → 候補を ↑↓ で選び **Enter / Tab** で入れる（**esc** で閉じる）。`/compact` などはそのまま送ると効く |
| スレッドを切り替える | ⌃Tab / ⌃⇧Tab、または ⌥⌘← / ⌥⌘→ |
| 過去のスレッドを復元する | **⌘⇧H**（スレッド履歴） |
| スレッドを閉じる | パネル内で ⌘W |
| AI を全画面にする | **⌘⇧⏎**（中央エディタを Agent に差し替える） |
| 過去の時点へ戻す | transcript 内の checkpoint 行をクリック |
| ファイルを渡す | エクスプローラや Finder から composer へドラッグ（@メンションになる） |
| 変更を確認する | ツールカードの `+N −M` から diff タブを開く |

**モデル / 思考量 / 権限モード**は composer 下のピルで選ぶ。選んだ値は次の新規スレッドに引き継がれる。
**エージェント（どの AI か）**は会話を始める前だけ変更できる。別のエージェントを使うときは新しいスレッドを作る。

### 通知

- ターンが終わると右下にトーストが出る（例: 「●rope設計 完了」）
- 通知音は猫の声。**完了**は裏のウィンドウのとき、**入力待ち**はそのスレッドが見えていないときだけ鳴る
- 音は設定 `sound_done` / `sound_waiting` で `nyaan` / `nya` / `mew` / `system` / `off` / 任意のファイルから選ぶ

### Todo ボード

コマンドパレット「表示: Todo ボード」、またはレールの Todo アイコン。`.necoder/todos.md` を板として表示する。

- ✨ 今日の計画: ROADMAP と `git status` からタスクの下書きを作る
- タスクをスレッドへ送ると、完了時にエージェントが自分でチェックを付ける

### MCP サーバ

**設定 → MCP サーバ** で、エージェントに持たせる道具（MCP サーバ）を有効化する。
`~/.codex/config.toml` / `~/.claude.json` / `~/.cursor/mcp.json` にあるサーバは自動で一覧に載る（既定は無効）。

## 9. Fleet モード（複数エージェントの並走）

1 つのリポジトリで、複数のエージェントに別々の worktree で並行作業させるモード。

### 入り方

**⌘⇧M**、titlebar の `Editor | Fleet | Chat` の Fleet、またはレールの Fleet アイコン。
要対応があると Fleet ボタンに `◐ 2` のような件数が出る。

### 画面

```text
レール | Fleet サイドバー          | 系譜の帯（ブランチの分岐と統合）
      |  ⚑ Captain              |  舞台: Task カード 1〜3 枚
      |  要対応（裁くもの）       |   ┌ ● 名前 ⎇ branch [状態] …… [次へ] ⤢ ⋯
      |  ⌂ main（統合先）        |   │ スレッド | 変更（変更レビュー）| ターミナル | ファイル | ＋▾
      |  Task 行 …              |   └ composer
      |  ＋ Task（⌘N）           |  下段: ニュース / ターミナル
```

### 基本の流れ

1. **⌘N（＋ Task）** で依頼を 1 つ書く → **⌘⏎**
   - `task/<名前>` ブランチと worktree が作られ、エージェントが作業を始める
2. サイドバーで状態を見る。**要対応**に出たものだけ対処する（許可 / 確認 / 修正の指示）
3. Task カードの **次へ** を押して進める（稼働中 → レビューへ → Integrate → 片付け）
4. **Integrate（main への統合）は必ず人間が押す**

Task の変更から開く diff は、Task を切った時点の commit（base）と作業ツリーを比べる。題名は `<名前> ⇄ <base の短い SHA>` になり、エージェントがコミット済みの変更も出る。

### 主なキー

| キー | 動作 |
|---|---|
| ⌘⇧M | Editor ⇄ Fleet |
| ⌘N | ＋ Task |
| ⌘0 | Captain へ |
| ⌘⇧U | 次の要対応へ |
| ⌘⇧1 / 2 / 3 | 舞台に 1 / 2 / 3 枚並べる（◫ でピン留めした Task を並べる） |
| ⌘⇧G | 系譜の帯を畳む / 展開 |

### Captain（任意）

Captain は、目標を Task に分解して起動・レビューまで采配するスレッド。コードは書かず、Integrate もしない。
任命するには **設定（⌘,）→ AI エージェント** で、使いたいエージェントの行の **Captain にする** を押す。
任命中の行は `⚑ Captain` と表示され、もう一度押すと解任する。Fleet サイドバーの「Captain を任命する」を押してもこのページが開く。
未任命でも Fleet は使える（settings.json の `captain_agent` に直接書いても同じ）。

このボタンが更新するのはユーザー設定。プロジェクトの `.necoder/settings.json` に `captain_agent` がある場合はそちらが優先されるため、その設定を編集・削除して変更する。

### Task の片付け（⋯ メニュー）

下の段ほど残るものが減る。

| 操作 | 残るもの |
|---|---|
| カードを閉じる | Task・worktree・動いているエージェント |
| エージェントを止める | Task・worktree |
| Task を終了 | worktree（ディスク上） |
| worktree を削除 | ブランチ |
| ブランチごと削除 | なし |

削除の前に、失う未コミットの変更と未統合のコミットの数が表示される。

### 準備スクリプト

`.necoder/worktree-setup.sh` を置くと、worktree 作成直後に 1 回実行される。`.env` のコピーや依存のインストールに使う。
＋ Task ダイアログの「作る」でテンプレートが書き出される。

## 10. Chat モード（プロジェクトに紐づかない会話）

claude.ai のように、特定のプロジェクトに属さない相談や資料づくりをする場所。

### 使い方

1. **⌘⇧J**（または titlebar の Chat）で入る。窓の縁が無彩色になる = プロジェクトの外にいる
2. **⌘N** で新しいチャット
3. ファイルや画像を composer へドラッグ / 貼り付けして渡せる
4. エージェントが作った HTML / Markdown は、右側にプレビューで自動表示される

### ファイルの置き場所と権限

- 会話ごとのフォルダ: `~/Documents/necoder/<日付 最初の文>/`。成果物はその中の `artifacts/`
- necoder を消してもファイルは残る。置き場は設定で変えられる
- エージェントが書けるのは **そのチャットのフォルダと、渡したファイルだけ**。渡したファイルへの書き込みは最初の 1 回だけ確認される

### 一覧の操作

- 検索欄: タイトルと本文を検索
- 右クリック: ピン留め / フォルダを表示 / 会話を Markdown で書き出す / 削除
- 削除のとき、フォルダのファイルは既定で**残す**（消す場合も OS のゴミ箱へ移す）

使っていないチャットのエージェントは一定時間（既定 10 分）で自動停止し、次の送信で会話を引き継いで再開する。

## 11. Remote SSH

リモートマシン上のプロジェクトを、ローカルと同じ操作で編集する。

1. レールの **＋ → SSH**（またはレールの SSH アイコン）でホストを選ぶ
   - コマンドラインからは `necoder 'ssh://user@example.com:22/home/user/project'`
2. システムの OpenSSH 設定（`~/.ssh/config`・鍵・ssh-agent・ProxyJump）がそのまま使われる
3. 必要なサーバは自動で配備される（チェックサム検証つき）

- リモートのプロジェクトはレールのアイコン右下に server バッジが付く
- statusbar の **SSH** チップが接続状態を表す（緑 = 接続済み / 黄 = 接続中 / 赤 = 切断）。「再接続」で即座に張り直せる
- リモートの統合ターミナルで `ne .` を実行すると、そのディレクトリを接続元のウィンドウで開く

### スマホから見る（リモート管制）

**設定 → スマホ連携 → 接続用QRを発行** で、スマホの PWA とペアリングできる。QR は 5 分有効。
詳細は [`REMOTE-CONTROL.md`](./REMOTE-CONTROL.md)。

> 社外サービス（リレー）を経由する機能。業務プロジェクトで使う前に、所属組織の情報セキュリティ規程で可否を確認すること。

## 12. Windows でのキーの違い

基本は `⌘` → `Ctrl`。VSCode の作法に合わせて、次のキーが変わる。

| 動作 | macOS | Windows |
|---|---|---|
| 単語単位の移動 / 選択 / 削除 | ⌥← ⌥→ / ⇧⌥← / ⌥⌫ | Ctrl+← → / Ctrl+Shift+← / Ctrl+Backspace |
| 文書の先頭 / 末尾 | ⌘↑ / ⌘↓ | Ctrl+Home / Ctrl+End |
| 置換 | ⌥⌘F | Ctrl+H |
| カーソルを追加 | ⌥⌘↑ / ⌥⌘↓ | Ctrl+Alt+↑ / ↓ |
| 前後のプロジェクト | ⌃⌘↑ / ⌃⌘↓ | Ctrl+Alt+Shift+↑ / ↓ |
| 系譜の帯（Fleet） | ⌘⇧G | Ctrl+Alt+G |
| やり直し | ⌘⇧Z | Ctrl+Shift+Z または Ctrl+Y |
| 終了 | ⌘Q | Alt+F4 |
| ターミナル内のコピー / 貼り付け / すべて選択 | ⌘C / ⌘V / ⌘A | Ctrl+Shift+C / V / A |
| ターミナル内の検索 / クリア | ⌘F / ⌘K | Ctrl+Shift+F / K |

emacs 風の ⌃ キーはエディタでは使えない（矢印キーで代用）。ターミナルの中では Ctrl + 文字（Ctrl+C・Ctrl+F・Ctrl+W・Ctrl+P・Ctrl+J など）はそのままシェルやアプリへ届く。そのため、ターミナルにフォーカスがある間は Ctrl+P（ファイルファインダ）や Ctrl+J（ターミナルの開閉）などは効かない（ターミナルの外をクリックしてから使う）。

## 13. 設定・テーマ・色

### 設定画面（⌘,）

左のナビでページを選ぶ: **AI エージェント / MCP サーバ / 外観 / リモート / 動作とエディタ**。
ファイルで編集したいときは、コマンドパレット「設定: settings.json を開く」。

| 置き場所 | 効く範囲 |
|---|---|
| アプリの `settings.json`（macOS: `~/Library/Application Support/necoder/`） | 全体 |
| プロジェクトの `.necoder/settings.json` | そのプロジェクトだけ（`color` / `icon` など） |

よく使う設定:

| キー | 既定 | 意味 |
|---|---|---|
| `theme` | `necoder-dark` | テーマ名 |
| `font_size` / `tab_size` | `13` / `4` | 文字サイズ / タブ幅 |
| `density` | compact | 行の密度（compact / cozy）。**未実装**: 値は読むが、まだ画面に反映されない |
| `soft_wrap` | `false` | 折り返し表示 |
| `format_on_save` | `false` | 保存時にフォーマット |
| `locale` | OS に従う | UI の言語（日本語 / 英語） |
| `submit_on_enter` | `false` | Enter で送信するか |
| `sound_done` / `sound_waiting` | `nyaan` | 完了 / 入力待ちの通知音 |
| `reduce_motion` | `false` | スピナー等の動きを止める |
| `captain_agent` | なし | Fleet の Captain に使うエージェント（設定 → AI エージェントで選べる） |

設定画面のトグルは settings.json へ書き込む。settings.json を手で編集していて JSON として読めない状態（末尾のカンマ・コメントなど）のときは、ファイルを上書きせず「settings.json を読めないので保存しませんでした」と理由つきで知らせる。直してから押し直す。

### テーマ

- **⌘K ⌘T** でテーマ選択（選んでいる間はライブプレビュー）
- 同梱: necoder Dark / Light・Solarized Dark / Light・Gruvbox Dark・Catppuccin Mocha・High Contrast Dark
- 自作テーマ: 色トークンを上書きする JSON を `~/Library/Application Support/necoder/themes/*.json` に置く

テーマ（画面の配色）とプロジェクト色（識別）は別の設定で、どのテーマでもプロジェクト色は同じ場所に出る。

## 14. 困ったとき

| 症状 | 対処 |
|---|---|
| AI のスレッドが始まらない | `claude` CLI のインストールとログインを確認する（設定 → AI エージェント） |
| モデルのピルが `—` のまま | 接続中。エージェントがモデル一覧を返すまで待つ |
| 「セッションが切れました」 | 「再開」を押すか、そのまま次を送信する（可能なら前回の会話を引き継ぐ） |
| エージェントが作ったファイルが見えない | エクスプローラ右上の ↻ |
| キーが効かない | レールにフォーカスがあると編集キーは効かない。Esc で作業面に戻る |
| 不具合を報告したい | **ヘルプ → バグを報告**（issue の下書きが作られる） |

- ログ: `~/Library/Application Support/necoder/logs/`
- クラッシュレポート: `~/Library/Application Support/necoder/crashes/`
- necoder はテレメトリを送信しない。通信するのは、エージェント・SSH ホスト・リレーなど自分で始めたものと、GitHub Releases への更新確認だけ
