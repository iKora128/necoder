# necoder-router —— ACP プロバイダとして君臨する

necoder の裏側に置く**推論のルーター兼課金基盤**の設計。エディタ（necoder）と推論基盤
（ai and / gisium 等）の間に立ち、「どのモデルを・どのリージョンで・誰の枠で」使うかを決める。

- 対になる文書: `docs/ARCHITECTURE.md`（necoder 本体の crate 配置）/ `docs/DECISIONS.md`（判断ログ）
- 状態: **設計中**。実装未着手（2026-09-19 起票）

---

## 1. 立ち位置 —— 何になりたいのか

**ACP エコシステムの「繋ぎ先」として第一想起を取る**のが目的。necoder 専用にはしない。
Zed からも CLI からも繋がる ACP エージェントであることが、そのまま普及経路になる。

```
      ┌──────────── クライアント（ACP を喋るもの） ────────────┐
      │  necoder     Zed     その他 ACP クライアント            │
      └──────────────────────┬─────────────────────────────────┘
                             │ ACP (stdio)
                   ┌─────────▼──────────┐
                   │   necoderacp       │  ← ローカルプロセス。無料配布
                   │   （dsh 同梱）      │
                   └─────────┬──────────┘
                             │ HTTPS (OpenAI 互換)
                   ┌─────────▼──────────┐
                   │  necoder-router    │  ← 本文書の対象。Cloudflare
                   └─────────┬──────────┘
                             ├──▶ ai and / gisium   （国内 GPU・JP）
                             └──▶ Fireworks 等       （米国・US）
```

## 2. 決まったこと（2026-09-19）

| # | 判断 | 根拠 |
|---|---|---|
| R-1 | **ACP プロトコルは自作しない**。`agent-client-protocol` に乗る | 自作するとエコシステムから切れる。necoder は既にクライアント側を 4000 行書いており仕様理解がある |
| R-2 | **ハーネスは自作しない**。DeepSeek Harness（dsh・MIT）を採用 | ハーネスの品質は既にコモディティ（codex / opencode / dsh すべて OSS）。差別化にならないものは作らない |
| R-3 | **necoderacp はローカルプロセス**。クラウド常駐しない | opencode / Claude Code / Gemini CLI と同じ形。ソースコードがマシンから出ないことが最大の売り文句になる |
| R-4 | **課金は定額サブスク**（Pro / Max 5x / Max 20x）。前払いチャージにしない | 実装が減る（meter 不要・残高の厳密な直列化不要）／盗難カードでクレジットを買って転売する不正が成立しない／ユーザーが理解できる |
| R-5 | **計上と上限は Cloudflare AI Gateway** に寄せる | Custom Provider（OpenAI 互換）に対応し、custom metadata 単位で spend limit をかけられる。自作コードが目に見えて減る |
| R-6 | **リージョンはモデル名の一部**にする（`DeepSeek V4 (JP)` / `(US)`） | 選んだ瞬間にデータの行き先が確定する。説明と監査が一貫する |
| R-7 | **安さでは戦わない**。差別化はデータ経路とクライアント | 単価の下限を決めるのは GPU 調達と電力で、日本は不利。値段は翌週に合わせられる |
| R-8 | **外部ルーターは US リージョンにのみ使ってよい**。JP は直接契約 | 「中国を経由しない」を売るなら、経路を保証できない中継を挟んだ時点で売り物が消える |
| R-9 | Cloudflare の Unified Billing（上流への支払い代行・手数料 5%）は**使わない** | ai and と直接契約するので不要。5% は粗利に対して重い |

## 3. 何で勝つか / 何で勝たないか

| | 評価 |
|---|---|
| ハーネスの品質 | ✗ コモディティ。良い工夫は数週間で横並びになる |
| 推論の安さ | ✗ 構造的に不利。補助金前提の商売は事業ではない |
| **データ経路の保証** | ◎ 法務と契約なので海外勢が構造的に出せない |
| **クライアント（necoder）** | ◎ codex も dsh も opencode もエディタを持っていない。ここだけは唯一 |

**市場の核**: 「DeepSeek / Qwen は使いたいが、中国を経由したくない」。
DeepSeek V4 系は MIT、Qwen3 の open-weight は Apache-2.0 なので、**重みを国内 GPU に載せて商用提供する
ことが合法**。公式 API を使うとデータは中国に行くが、自前ホストなら中国と一切通信しない。
米国では Fireworks / Together がこの形で成立している。

**堀は技術ではなく書類**: 国内リージョン完結・学習に使わない契約・監査ログ・日本法準拠。
「言えること」ではなく「調達で通る書類が先に揃っていること」が参入障壁になる。
ISMAP / セキュリティ監査報告書 / 契約ひな形 / 稟議に添付できる構成図。技術より先に着手する価値がある。

## 4. モデルの見せ方

AI Gateway に **Custom Provider を2本以上**立て、necoderacp のモデル一覧にリージョン込みで並べる。

```
DeepSeek V4  (JP)   国内完結
DeepSeek V4  (US)
Qwen3        (JP)   国内完結
Qwen3        (US)
```

- リージョン選択は**サーバ側で縛る**。クライアント設定だと「そう設定していたはず」しか言えず、
  監査の証拠にならない
- necoder の色設計（レール）と相性がよく、JP / US をレールの色で分けられる

## 5. 課金

内部は**円（原価）で枠を切り**、外部には**倍率**で見せる。

| プラン | 月額 | 枠 | 内部の上限（原価） |
|---|---|---|---|
| necoder Pro | ¥3,000 | 基準 | 月 ¥1,200 分の推論 |
| necoder Max 5x | ¥15,000 | 5倍 | 月 ¥6,000 分 |
| necoder Max 20x | ¥50,000 | 20倍 | 月 ¥24,000 分 |

※ 金額は仮。ai and の卸値が出た時点で確定させる。

- **倍率で見せる利点**: 原価が変わっても比率が壊れない。モデルを差し替えても「5倍」は5倍のまま
- **粗利が設計段階で確定する**。`売価 − 原価上限` が最低粗利。使い切らない人の分が全部粗利になる
  （従量転売だと数%しか残らない。OpenAI も Anthropic もサブスクなのはこれが理由）
- ユーザーにトークン数は見せない
- モデルごとの消費係数（JP=1.0 / US=0.8 等）は原価で切っているので自動的に効く
- **枠のリセットは月次から始める**。Claude Code の 5 時間ローリングは GPU の瞬間負荷を平すための
  仕組みで、ユーザーが少ないうちは不要。「月初に使い切る人」が出たら日次上限を足す
- 決済は Stripe（**普通のサブスク1本**。meter も従量請求も要らない）

## 6. バックエンド構成 —— マシンは要らない

| 役割 | 何を使う |
|---|---|
| キー発行・失効・プラン状態 | D1 |
| プラン別の上限 enforce | **AI Gateway の spend limit**（metadata = `user_id`） |
| 上流への中継・metadata 付与 | Worker |
| 請求の台帳（自前ログ） | D1 / Analytics Engine |
| 決済 | Stripe |

- GPU / VM / コンテナは**ゼロ**。立ち上がりのインフラ費用は月 $10〜20 程度
- 固定費リスクは**上流の最低コミット**だけ。ai and との条件次第

### クラウド常駐（サーバ側でツール実行）が要るのはいつか

- エディタを閉じた後もタスクを走らせたい / CI から叩きたい / チームでセッションを共有したい

ここに来て初めてコンテナが要る。**最初は不要**。ローカル形で普及させた後に足せるので順番として正しい。

## 7. 金に関わる罠

| # | 罠 | 対策 |
|---|---|---|
| T-1 | **残高の二重使用**。同時リクエストが同じ残高を読んで両方通る | 定額プラン + AI Gateway の spend limit でほぼ解消。厳密さが要るならアカウントごとの Durable Object で直列化 |
| T-2 | **usage の取りこぼし**。トークン数はストリーム最後の `usage` で確定するため、ユーザーが中断すると課金できないまま原価だけ発生する | Worker で `ctx.waitUntil()` を使い、クライアントが切れても上流を読み切って計上する。**必ず踏むので最初から入れる** |
| T-3 | **トークンの種類ごとに単価が違う**。cache hit した input は1桁違う | `{ provider, model, input, cache_read, cache_write, output }` に正規化してから価格表に当てる。価格表に卸値と売値を両方入れ、粗利がリアルタイムで見えるようにする |
| T-4 | **AI Gateway の Analytics は集計で遅延する** | Gateway は「使いすぎを止める仕組み」、自前ログは「請求の台帳」。二重に記録して突き合わせる |
| T-5 | **決済を持つと義務が付いてくる** | 特定商取引法の表記・インボイス・返金対応。前払いチャージを避けることで不正利用の的は大幅に減る |

## 9. 実装順序

| | やること | 目安 |
|---|---|---|
| R0 | AI Gateway に Custom Provider を2本登録、curl で疎通 | 1日 |
| R1 | necoderacp: dsh のモデルプラグインを1本書き、necoder から ACP で繋ぐ（**BYOK**） | 1〜2週 |
| R2 | Worker: necoder のログイン検証 + `user_id` を metadata に付与 | 数日 |
| R3 | Stripe: サブスク3プラン、spend limit との紐付け、自前ログとの突き合わせ | 1週 |
| R4 | リージョンのサーバ側強制、監査ログ | — |

**R1 が本体**。R0 は ai and の回答を待たずに（US 側のプロバイダで）今日から始められる。

**BYOK で一度出す価値**: R1 だけで「中国を経由しない DeepSeek が necoder から使える」が成立する。
課金インフラをゼロのまま需要を確かめられる。レジ（R2/R3）は使う人がいると分かってから足す。

## 10. ライセンス境界

- necoder 本体は **AGPL-3.0**。necoder-router を SaaS で提供する際、**AGPL のネットワーク条項が
  サーバ側コードに及ぶか**を設計段階で切る必要がある
- **別プロセス・ACP 越しの独立実装**（necoder のコードを一切共有しない）にすれば分離できる。
  「共通の型を crate で切り出して両方から使う」をやった瞬間に境界が怪しくなる
- dsh は **MIT**、DeepSeek V4 系の重みは **MIT**、Qwen3 の open-weight は **Apache-2.0**。
  いずれも necoder の AGPL と衝突しない
