### 1.2 アイデンティティ色

- **プロジェクト色パレット（自動巡回）**: indigo `#7c8cf8` → teal `#34d3b6` → amber `#f0a24b` → rose `#ef7d9b` → green `#85c46c`
- **アイデンティティ・パレット（ピッカーの正典）** = `theme_core::IDENTITY_PALETTE_HEXES`: 上の巡回5色 + 予約色（Claude バレット `#d97757`・スレッド色・選択面 `#7d9bd8`）と衝突しない厳選色（cyan / chartreuse / violet / magenta / graphite）。**巡回もピッカーもこの1本が出所**
- 優先順: `.necoder/settings.json` の `color` > **ユーザーの手動選択** > パレット巡回。手動選択の導線 = レール右クリック / **⌘K⌘C** / コマンドパレット「表示: プロジェクトの色を変更」→ 厳選スウォッチ or **任意 hex 入力**
- 任意 hex はエスケープハッチ: §1.3 の流れ先（許可リスト）は変えない。**細い accent としての可読性はユーザー責任**（Peacock と違いコントラスト自動計算はしない）
- **スレッド色パレット（自動巡回）**: `#61afef` → `#e5c07b` → `#c678dd`（プロジェクト色と独立）
- accent-dim = プロジェクト色 16% 透過（パレット選択面・タイル選択輪郭のみ）

## 2. レール（プロジェクトの方向感覚・常設）

- 項目 = 30×30 角丸8。中身は優先順: `.necoder/settings.json` の `icon`（絵文字 or 画像パス）> 規約パス `.necoder/icon.png`（jpg/jpeg/webp も可・置くだけで効く）> プロジェクト名の頭文字（例: 印）。画像でも**色の枠は残す**（識別は色・画像は装飾＝§1.3）
- 状態: active = プロジェクト色の枠 + 2px リング / hover = 枠のみ / 通常 = 色 14% の面 + 35% の枠
- 下部に**実行中スレッドのドット**（5px・スレッド色・実行中 pulse 1.6s）→ 他プロジェクトの動きが常に見える
- ＋ = **統一オープン**（`open_launcher`）: フォルダ / ファイル / リモート + **最近（local + remote 混在・opened_at 降順）** を 1 枚の広いファジー面に。最近行は ●識別色 ＋ 実行中ドット、リモートは `host:path` で識別。⏎ = 現レールに開く。⌘O は開いているプロジェクト間の切替（別物）。左クリック = 窓内切替（ARCHITECTURE §5）。ドラッグ並び替えは v1
- **右クリック = コンテキストメニュー**（M10-2）: 色スウォッチ + 「その他の色…」（フル hex ピッカー）／新しいウィンドウで開く／レールから外す／(worktree タブのみ) worktree を削除・worktree ごとブランチを削除。破壊的操作は二段確認（もう一度クリックで実行）
- **アクティビティアイコン**（下部・explorer/search/git/todos/agent/terminal/remote）: 表示中のビュー/ドックだけプロジェクト色・他は fg2（§1.3・VSCode の Activity Bar 準拠）。active 判定 = explorer:左ドックがツリー / search:検索パネル開 / git:git パネル開 / todos:板開 / agent:右ドック表示 / terminal:下ドック表示 / **remote:SSH ホストピッカーを開くアクション（server アイコン・アクティブプロジェクトがリモートなら色付き・#2）**
- **リモート slot**（レールのプロジェクト）: SSH 接続先はモノグラム右下に **server バッジ**（プロジェクト色・ローカルと見分ける・#2）。窓縁 2px 枠（§1.3）と併用
- **レール = 最後に触った面**（2026-09-03）: レールのどこか（項目でも空き地でも）を押すと `rail_active` が立ち、面が bg1 に上がる。立っている間は **⌘{ ⌘}（タブ切替）が前後のプロジェクト切替**に化ける（⌃⌘↑↓ と同じ循環・行き先名フラッシュあり）。レール外をどこか押すと落ちてエディタタブ宛てに戻る。フォーカスは動かさない（突いた後そのまま文字を打てばエディタに入る）。トラックパッドで「突いて ⌘}」の動線

## 4. エクスプローラ（3ビュー + ファイルブラウザ挙動）

- ヘッダ = **上位階層ブレッドクラム**（`Work › experience › necoder`、現在=太字 fg0、親=fg2・クリックで上へ。プロジェクトの外に出たら「フォルダブラウズモード」— 任意フォルダを右クリック→プロジェクトとして開ける）+ 右端に **更新ボタン**（Lucide `refresh-cw` 12px・fg2 → hover fg0/bg3。ツリー再構築 + git 色 + gutter diff を読み直す。監視の取りこぼし（エージェントが作ったファイル等）の明示的な逃げ道・2026-09-03）
- フッタ = ビュー切替アイコン3種（ツリー/カラム/アイコン）+「表示モード」ラベル
- **ファイルタイプアイコン**（3ビュー共通・`file_icon_path`）: 拡張子/名前から SVG アイコンを引く。言語ロゴ = **Simple Icons**（CC0・rust/js/ts/tsx/py/go/json/yaml/toml/html/css/md/shell/c/cpp/git/docker）、フォルダ・汎用 = **Lucide**（ISC・folder/folder-open/file/text/image）。すべて**単色マスク**で描き、色は `file_type_color`（syntax パレット）で薄く付ける＝**形で見分け、色は識別に集約**（多色ロゴにはしない）。フォルダは開閉で folder/folder-open を切替（ツリーは `is_expanded`・カラムは選択経路上）。未知拡張子は汎用ファイルへフォールバック
- **ツリー**: 行 = chev(10px) + **ファイルアイコン(14px)** + 名前 + git ドット（右寄せ・mod=warn色/add=ok色）。インデント 14px/段。選択 = bg3 + 左バー2pxプロジェクト色
- **カラム**（Miller）: 列 150px 固定・最終列 flex。選択経路 = bg3+左バー。下部パスバー 26px
- **アイコン**: ナビヘッダ（‹ › ↑ + 現在フォルダ名 + 項目数）、grid minmax(84px)、タイル = ファイルアイコン(30px) + 名前 10.5px 省略。フォルダ=固定ブルー・書類=言語アイコン。下部パスバー
- **右クリックメニュー（全ビュー共通）**: 開く / *(dir)* **ここをプロジェクトとして開く**（現レールに再ルート・remote は SSH 接続を再利用＝browse-first の「開く」主導線）/ **新しいウィンドウで開く** / *(file)* 分割して開く / ─ / Finder に表示 / パスをコピー `⌥⌘C` / 名前を変更… `⏎` / ─ / ゴミ箱に入れる `⌘⌫`
- **D&D（Finder 風・全ビュー・local のみ）**: 受け面 = フォルダ行/セル その中へ（識別色 16% 面）・余白 そのビューの文脈フォルダへ（ツリー=ルート / カラム=その段 / アイコン=現在フォルダ。識別色 6% 面）。ツリーのファイル行への drop は同じフォルダへ（Finder のリスト表示と同じ）。**エクスプローラ内のドラッグ = 移動**・**Finder からのドラッグ（ExternalPaths）= コピー**（元は動かさない安全側・VSCode と同じ。フォルダは再帰）。同じ親・自分自身/配下への drop は no-op。上書きしない（同名は toast で断る）。composer への @メンションドラッグは同じドラッグの別の受け先（フォルダもドラッグ可）。**行/セルの開く・開閉は click（離した時）**: mouse-down 発火だと掴んだ瞬間に開いてしまい D&D と衝突する（ドラッグ成立時はクリック合成が破棄される＝誤発火しない）
- ファイル操作（作成/リネーム/移動/削除）は **undo 可能**にする（VSCode 同様）

- **AI 全画面（⌘⇧⏎ / ヘッダの ⤢ / メニュー「AI を全画面」・2026-07-27、2026-08-08 改訂）**: **中央のエディタを Agent パネルに差し替える**面。冗長になる右の Agent ドックだけ畳み、**左ドック（ファイルブラウザ）と下ドック（ターミナル）は各自の ON/OFF に従う**（全画面が全部を消さない・本人要望）。純チャット（ファイルを見ない）にしたければ左ドックを OFF にする＝明示操作に寄せる。レールは常に残す。編隊モードとは排他（どちらも窓を丸ごと使う面）
- **モデル / 思考量は sticky**（2026-07-27）: ピルで選んだ値を `default_model` / `default_effort` へ書き戻し、次の新規スレッド・復元スレッドがそれで開く。**エージェント（どの AI か）だけは sticky にしない** — 環境の選択なので 1 スレッドの都合で全体が動くと事故になる（DECISIONS §8 のドリフト禁止）。Agent ピルは**未送信スレッドでだけ変更可**。最初の送信後はラベル表示（シェブロン無し）に固定し、別 Agent は新規スレッドで選ぶ。thread 固有 Agent は DB に保存・復元する。各ピルのメニューは外側クリック（他タブを含む）で閉じる。**Agent ピルと選択メニューの各行にはブランドバッジ**（スレッドタブ / 設定画面と同一在庫＝`AgentKind.icon`・無ければモノグラム。ピル 12px / メニュー行 14px。Mode/Model/Effort は文字のみ）

## 11. 編隊（マルチエージェント）モード（M14）

複数エージェントを worktree ごとに並走させ、**色（識別）× 系譜グラフ（構造）× 動き（状態）で指揮する**専用ビュー。herdr の「設定不要の状態一覧」は設計比較に限り、ACP と necoder の状態型から独立に実装する。**状態に色相は持ち込まない**（§1.3・§8）。入口 = レールの編隊アクティビティ or トグル。通常ビュー（ファイル中心）と明示的に切替。**左のファイルブラウザ/タブは残す**（focus 中エージェントの worktree を映す）。mock 編隊モードが見た目の正。

- **レイアウト**: レール | 左カラム | 中央（系譜グラフ ＋ N セルグリッド）| 下段ドック。**中央はタブ 2 面**（P3・2026-07-23）: **管制（Control）** / グラフ。既定は当面グラフ（ドッグフーディング後に再判断）
  - **左カラムは solo と同じ排他規則**（2026-07-27）: Todo / git / エクスプローラを開いていればそれ、無ければ **herd**（編隊の既定）。レールのアクティビティアイコンが両モードで同じ意味を持つ ＝ 編隊中にレールが死なない
  - **⚙ 設定**は編隊でも中央を占有する（solo と同じ）
  - **下段ドックはタブ 2 面**（2026-07-27）: **ニュース / ターミナル**。上縁ドラッグで高さ可変（60〜900px・solo の下ドックと同じ `bottom_height` を共有）・▾ で畳む。ターミナルは**アクティブ Task の実シェル**（cwd = その worktree）で、セルの Terminal surface と同じ実体。レールのターミナルアイコン / ⌃` はこのタブを切り替える
- **管制（Control）タブ**（FLEET-CONTROL-PLAN P3・ビジュアルの正 = `mock/fleet-dashboard.html`）: 上から ① ヘッダ（管制 repo ⎇ main + N worktrees・目標文・stat チップ **◐要対応**（>0 で err 色ボーダー）/ ✓完了未確認 / ●稼働 / ⇡統合・Σトークン合計+メーター）② 監督バー（**集約気分マスコット**＝編隊の最悪状態に追従: 承認待ち→祈る・15s 超→頬に手・実行中→打鍵・静穏→うとうと。監督は P6 まで「未任命」・総括は Tier2 まで決定論の事実文＝**✳ を付けない**）③ **要対応キュー**（左 336px・Blocked 経過時間順→Failed→Review→Done 未確認。カード内**インライン操作** = 許可/常に許可/拒否（ACP 広告ラベルそのまま）・Radar 実行・Integrate・確認（Done→Idle の確認済み遷移）・破棄。先頭カードに「次 ⏎」バッジ）④ **稼働カード**（右・digest + ▰▱ plan メーター + files + tok + 経過。クリックで没入=セル拡大へ）⑤ **統合パイプライン**（PLANNED→WORKING→BLOCKED→REVIEW_READY→MERGE_READY→INTEGRATED→FAILED 列にタスクチップ・changes_requested は REVIEW_READY 列・integrating は MERGE_READY 列に畳む）⑥ ニュース（P2 常設）。**⏎ = キュー先頭へ没入**（keymap context `FleetControl`）
- **✳ と破線の意味論**（管制の規律・FLEET-ARCHITECTURE）: **✳ テラコッタ = LLM 生成テキストの印**（Tier 2 要約のみに付す・事実層/Tier1 には付けない）。**破線 = 画面推定**（Herdr 由来・P7。確定情報と視覚的に混ぜない）
- **遷移スナップショット（digest・P1）**: 状態遷移時のみ生成（ポーリング無し）。Blocked=許可待ちの内容 / Done=最後の発言の末尾 1〜2 文 / Failed=エラー文 / Working=ライブ素材（実行中ツール + plan 進行中・保存しない）。herd 行の 1 行サブテキスト・セルヘッダ帯・管制カードが共用
- **ニュース（P2）**: `task_events` の鏡（= 台帳に書くのと同じ場所で積む・起動時 backfill）。行 = 相対時刻 + 帰属チップ（スレッド/Task 色・**監督は丸チップ**）+ 太字名 + イベント文。エージェント別ミュート（🔔/🔕）はトースト/完了音だけ止め、ニュースには残る。完了音は **window 非アクティブ時のみ**
- **herd サイドバー（herdr の核・常設）**: プロジェクト別グループ。行 = `activity_dot`（スレッド色 × 形と動き＝§6）＋ 左バー 2px スレッド色 ＋ **エージェントアイコン**（`AgentKind.icon`・§6）＋ 名前 / 1行状態＋**最新時刻**（最終入力・未入力なら開始。両方はホバーの tooltip）・トークン。末尾に 5 状態の凡例（**形**の説明＝色は識別なので中立）。下段に focus 中エージェントの worktree ツリー（git 色つき）
- **状態は色相を持たない**（§1.3・§6・§8 の `activity_dot` を共用）: ⠿ 作業中(点字スピナー回転・2026-07-25 選定) / ◐ 承認待ち(半円・速い脈動) / ✓ 完了・未確認(静止) / ○ 待機(淡) / · その他。色は常にスレッド識別色。ACP は `ThreadActivity` で確定・統合ターミナルは画面スキャンで推定（M14）
- **focus-follows-agent**: herd 行 / グリッドセルをフォーカス → 左エクスプローラ・エディタタブ・下ターミナルがその worktree に張り替わる（レール切替と同じ `ProjectSession` 単位・ARCHITECTURE §5）。＝「今見ているエージェントのファイル」で真を一意化
- **系譜グラフ**: ネイティブ描画（webview 不使用・editor_view/terminal_view と同じ custom Element）。**扇形（Fan）既定** ＋ ツリー / カード / ハブの 4 表示（River は廃止し、Hub＝中央=リポジトリのハブ&スポークを追加）。ヘッダ右にスイッチャー（**アイコン＋語**・単体アイコンが曖昧なため語併記）＋ ⌄ で折り畳み（グリッドが上まで拡張）。レーン/エッジ=スレッド色・ノード=commit・**先端=状態（形と動き・色は据え置き）**・プロバイダバッジ・base からの fan-out とマージ。データは `git log --all --parents` でレーン自前計算
- **N セルグリッド**: 主セルは **TaskSpace（1 task = 1 worktree）**で、通常 View と同じ完全な AgentPanel を埋め込む。同じ Task の Agent は panel 内 thread tab。surface は Task / Terminal / Editor / Diff / Tests。既定 **＋Task** は常に `task/*` branch + linked worktree を作り、**＋Agent to this Task** だけが同じ worktree への複数 Agent を許す
- **セルの命名 / 削除の近道（2026-08-18）**: セルヘッダのタイトルを**ダブルクリックで改名**（herd 見出しと同じ機構＝§162 の `start_task_rename`）。改名は**表示名 `title` だけ**を変える — git ブランチ `task/*` と worktree フォルダは不変（表示と git 識別を分離。ブランチごと改名は「重い＝生きたエージェント/タブ/ターミナルの張り替え + git-safe 名の強制」なので採らない・2026-08-18 ユーザー合意）。手動改名は AI 自動命名に上書きされない（`is_placeholder_task_title`）。ヘッダに **🗑 worktree 削除**の近道（拡大 / ⋯ の間・押すと ⋯ の片付け最下段と同じ `request_worktree_delete`＝「失うものを数える」確認ダイアログ経由）。**Task セル（非 Integration）のみ**。herd の Task 見出しにも**ホバーで 🗑**。改名入力欄は編集場所（herd / セル）を `RenameSite` で持ち、編隊で herd とセルが同時に見えても同じ入力欄 Entity を二重描画しない
- **セルの片付け（⋯ メニュー・2026-07-27）**: 「× を押しても消えない / 消すのと画面から外すのの違いが分からない」への回答。**同じ 1 枚に全段を並べ、各行の副題に「何が残るか」を書く**。上から下へ残るものが減る:

  | 段 | 何が起きる | 残るもの |
  |---|---|---|
  | セルを閉じる（× と同じ） | 画面から外すだけ | Task・worktree・**動いているエージェント** |
  | エージェントを止める | 実行中ターンを中断（esc と同じ） | Task・worktree |
  | Task を終了 | 台帳を `archived` に。編隊/herd から消える | worktree（ディスク） |
  | worktree を削除 ⚠ | `git worktree remove` | ブランチ |
  | ブランチごと削除 ⚠ | worktree + `git branch -D` | なし |

  下 2 段は**確認ダイアログ**（次項）。実装はレールの `delete_slot_worktree_impl` へ委譲 ＝ **どこから消しても同じことが起きる**
- **worktree 削除の確認ダイアログ（2026-07-27）**: 「本当に消しますか？」は情報がゼロなので出さない。出すのは **git に数えさせた「失うもの」**:
  - `未コミットの変更 N ファイル — git にも残らず、元に戻せません`（`git status`）
  - `統合先に入っていないコミット N 件`（`git rev-list --count <integration>..HEAD`。比較先が引けなければ「比較できませんでした」と正直に出す）
  - ブランチごと削除なら `ブランチ <name> も削除します`
  - どれも 0 なら `失うものはありません（同じブランチから作り直せます）`
  0 件の行は出さない（0 を並べても読ませるだけ）。背景クリック / キャンセルで閉じ、**閉じる側は絶対に実行しない**
- **「次回から確認しない」は取り返しがつく削除にだけ効く**（`confirm_worktree_delete`）。未コミットの変更は reflog でも戻らないので、
  そこを 1 個のチェックボックスで無音化できるようにはしない。チェックボックスのラベルでその条件を明示する
- 旧・二段確認（同じ行をもう一度押させる）は**廃止**。押させる回数を増やしても情報は増えない
- **× は「閉じる」だけ**で、Task もエージェントも消さない。閉じた時にエージェントが走っていたら**トーストでそう言う**（黙って裏で走らせない）
- **セルは初回だけ自動配置**（`fleet_seeded`）。「空なら seed」だと最後の 1 枚を × した次のフレームに全セルが復活していた（2026-07-27 修正）
- **拡大は ⤢ の明示操作にだけ属する**。herd / グラフのタップは**拡大しない**（以前は必ず全画面になっていた）。既に拡大中なら枠を保ったまま対象だけ差し替える
- **linked worktree の判定は git に聞く**（2026-07-27）。「このセッションで worktree として開いたか」の記憶に頼っていたため、再起動すると worktree なのに削除メニューが消えていた
- **履歴（前の会話の復元）**: スレッドは DB 永続なので、編隊でも Agent パネルと同じ**スレッド履歴 Picker**（**アクティブプロジェクトのみ**・アーカイブ含む・detail に Σトークン＋開始/最終入力の相対時刻）から復元できる（＋タイル「履歴から復元」/ ⌘⇧T は直近）。編隊モード中に確定した会話は**グリッドのセルとして前面（拡大）に出る**。相対時刻は編隊/herd 表示中のみ 30 秒時計で更新（両方閉じたら自停止＝idle 予算）
- **Task lifecycle / integration**: planned → working / blocked → review_ready → merge_ready → integrating → integrated。Review は read-only Conflict Radar、main への write は明示 Integrate のみ。
- **編隊操作 API**: `necoder fleet create/list/status/wait/review/integrate` と同等 MCP tools。stable Task ledger を真実にするため Coordinator/UI の再起動を跨いで wait/resume できる。詳細は `FLEET-ARCHITECTURE.md`。
- 既存の**スレッド色貫通・宛先チップ・トークン常時表示**は編隊内でも不変。**キー**: 編隊トグル / ＋(パネル追加) / グラフ ⌄(折り畳み) / セルフォーカス(クリック)（既定キーは M14 で確定）
