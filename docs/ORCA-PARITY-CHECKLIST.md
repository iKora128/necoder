## 0. 前提

`necoder Dev.app` は常用の necoder と並べて動かせる。状態は `~/.necoder-dev` に分かれる。

```sh
cd /Users/daichi/Work/experience/necoder-parity-integ
./scripts/bundle-mac.sh release dev
open "target/necoder Dev.app"
```

- `dev` を付けると bundle ID `dev.necoder.editor.dev` の「necoder Dev.app」ができる。Info.plist の LSEnvironment が `NECODER_HOME`・GUI のソケット（`~/.necoder-dev/gui.sock`）・書類フォルダ（`~/.necoder-dev/documents`）を `~/.necoder-dev` の下へ向け、`NECODER_DEV_BUNDLE=1` で常用と共有する物（自分自身のアップデート・`ne` のシム・skill の置き場）に触れさせない。エージェントのレジストリの取り直しは止めないので、エージェントは常用と同じ版になる。置き場は `NECODER_DEV_HOME=<絶対パス>` を付けて組み立てると変わる。
- LSEnvironment が効くのは `open`・Finder・Dock から起動した時だけ。Dev の実体を端末から直接起動しない。
- 組み立ての途中で relay の `npm ci && npm run build` が走る（ネットと Node.js が要る）。Xcode の `metal` が無ければ実行時シェーダで組む。release の初回は数分〜十数分。
- Dock のアイコンが古いままなら `killall Dock`。絵は常用と同じなので、Dock と通知では名前「necoder Dev」で見分ける。
- 最初からやり直すには、Dev を終了して `rm -rf ~/.necoder-dev`。

Dev だけの物: 設定（`~/.necoder-dev/settings.json`・`keymap.json`）、DB（スレッド・注記・Task の台帳・使用量）、窓の状態、ログ（`~/.necoder-dev/logs`）、アカウントのフォルダ（`~/.necoder-dev/accounts/`）、Chat のフォルダ（`~/.necoder-dev/documents/necoder/…`）。最初は空なので、プロジェクトは開き直す。

常用と共有している物（Dev で触ると常用にも効く）:
- エージェントのログインと会話の記録（`~/.claude`・`~/.codex`）。常用で動いている会話を、Dev の ⌘⇧H から開いて続けない。
- skill の置き場（`~/.claude/skills`・`~/.codex/skills`）と `/usr/local/bin/ne`。Dev の設定画面の「入れる」「インストール」は、理由を出して何もしない（Dev の実体を指す skill やシムを常用と共有の置き場に書かないため）。
- `~/.ssh/config`（接続先の登録はここへ書く）と、接続先の `~/.local/share/necoder/remote`。
- git のリポジトリ。Fleet の Task は本物のブランチと worktree（`<repo>-worktrees/`）を作り、常用の Fleet に「外部の worktree」として出る。Fleet・Git・衝突・注記は使い捨てのリポジトリで試す（例 `git init ~/necoder-check`）。

CLI の項目の呼び方: 今の `/usr/local/bin/ne` は常用の実体を指す古いシム（素通しは `config|fleet|mcp` だけ）で、`ne terminal …` などは Dev に届かない。Dev の中のターミナル（`NECODER_HOME` と `NECODER_GUI_SOCK` を継ぐ）で次の別名を作る。外のターミナルから呼ぶ時は、頭に `NECODER_HOME=~/.necoder-dev NECODER_GUI_SOCK=~/.necoder-dev/gui.sock` を付ける。

```sh
alias nd='"/Users/daichi/Work/experience/necoder-parity-integ/target/necoder Dev.app/Contents/MacOS/necoder"'
```

SSH の接続先: 別の Mac なら Dev.app の中の server が配られる。Linux 用の server は Dev.app に入らない（`target/<triple>/release/` にある時だけ同梱）。一度 0.1.20 の server を配った接続先なら、それがそのまま使われる（通信の取り決めは変わっていない）。配っていなければ CI の成果物を `~/.local/share/necoder/remote/artifacts/<triple>/necoder-remote-server` に置く。

- [ ] エージェントの版: 起動して十数秒で ACP レジストリを取り直す（常用のキャッシュは claude-agent-acp 0.81.x・codex-acp 1.13.x）。`/` 補完・使用量・過去の会話を試すスレッドは、その後に作る。About に「アップデートを確認」が出ない（Dev は自分を更新しない）

## 3. 変更のレビューと注記

要点: 変更レビュー（O6）と注記（O7）。送る・再起動・並べ替えの流れはテストの作り物でしか通していない。R01・R02・R03・R07 の確認条件もここ。

- [ ] `⋯ N 行` で前後 20 行ずつ開く。ツリーを押すと見出しへ、`☰` で隠す。「比較」で Task の base / HEAD / ブランチ / コミット、「空白を無視」で空白だけの差が消える。外で変わると `↻ 新しい変更があります`、押しても読んでいた行は動かない（O6）
- [ ] 行にホバーで ＋（行を選んで `c`、⇧クリック / ドラッグで範囲も）→ 入力欄に日本語で書く。変換の確定 Enter は改行のまま保存しない。⌘⏎ で保存、Esc で取り消し（O7）
- [ ] 下端の「注記 N 件（未送信 M）」から飛ぶ・編集・解決・削除。「送る ▾」で既定（Editor はアクティブなスレッド・Fleet は Task のスレッド）へ → `path:行` と抜粋つきの 1 通が届き、表示中のタブは替わらない（O7）（課金あり）
- [ ] 作業中のスレッドへ送る → 送信待ちに積まれ、ターンが終わると裏のタブでも流れる。1 件を「解決」して「未解決だけ再送」→ 残りだけ 1 通で届く。注記は ⌘Q して起動し直しても残る（O7）（課金あり）
- [ ] 「☐ 見た」で畳んだファイルを外で書き換える → 印が外れて畳みが開き、見出しに「見た後に変更あり」（R01）
- [ ] 注記の行より上に 2 行足す・ファイルを改名する・比較の基準を変える → 注記は同じ中身の行へ移るか、見出しの直後の「位置が変わった注記」に出る。関係の無い行に黙って付かない（R01）
- [ ] 位置が変わった注記も元の抜粋ごと読め、送ると「（付けた時の場所・今の差分では見つからない）」付きで届く（R01）（課金あり）

- [ ] 「送る ▾」を開いたまま、宛先より前のスレッドを閉じるか並べ替える → 選んだスレッドに届く（R07）（課金あり）
- [ ] 「送る ▾」を開いたまま宛先のスレッドを閉じる → 送られず未送信のまま、送り先のメニューが開き直る（R07）

## 4. Design Mode と Web タブ
