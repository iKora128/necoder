# Pi と DeepSeek Harness（dsh）：サブスクで使えるか、ACP アダプタの実測、上位に置く案

調べた日: 2026-10-02。対象の版: Pi 1.0.0（npm 公開 2026-10-01）、pi-acp 0.0.34（2026-09-24）、dsh 0.2.0-rc.2（2026-09-29）、`@openma/deepseek-harness-acp` 0.4.35（2026-09-29・同梱の dsh は 0.1.7-rc.2）。[#38](https://github.com/iKora128/necoder/issues/38)（ハーネスと接続を差し替える計画）の下調べとして書いた。

## 結論

- **Pi は API キー以外でも使える。** 1.0.0 の `/login` からサブスク 7 系統に入れる（Claude Pro/Max、ChatGPT の 2 経路、GitHub Copilot、xAI、Kimi Code、Meta Muse）。ただし一次資料で Pi を名指しして認めているのは OpenAI だけ。Claude のサブスクは Pi では従量の extra usage になり、Anthropic の規約は第三者が Free/Pro/Max の資格情報で要求を通すことを認めていない。Google のログインは 2026-04-30 に Pi から外れた。
- **dsh にサブスクや定額は無い。** DeepSeek API の従量課金だけ。DeepSeek アカウントでサインインする経路も、Platform の残高から引かれる。
- **ターンは、ふつうに使う分には閉じる。** pi-acp、dsh-acp、dsh 公式の ACP のどれも、返答とツールと取り消しで、最後の更新の直後に閉じた。zeron がアダプタを捨てた理由（裏の作業でターンを開いたままにする）は、どちらでも起きなかった。崩れたのは pi-acp が失敗した時で、モデル側のエラーを黙って `end_turn` にし、pi が途中で落ちるとターンが二度と閉じない。
- **今回は `const AGENTS` に足さない。** `const AGENTS` に足すだけでは、ログイン状態の判定に Pi と dsh の分岐が無いので composer に出ず、いまのカスタム追加より後退する。そもそも pi-acp は失敗した時の扱いが粗く、dsh は本文がトークン単位で流れない。組み込みとして勧めるにはまだ早い。当面はカスタム（レジストリ）のまま既定のエージェントにして使う。上げる時の並び順、`AgentKind` の案、一緒に要る変更は ⑤ に書いた。

## 調べ方

- **Web**: 各社の規約・ヘルプ・料金ページと、Pi / pi-acp / dsh / dsh-acp のリポジトリを読んだ。引用はすべて原文を開いて確かめた（確認日は末尾の出典にまとめた）。
- **実測**: 一時ディレクトリ（`/tmp/pi-dsh-lab.*`）に `HOME` と npm の prefix を作り、`npm i` はその中だけで行った（グローバルには入れていない）。本人の `~/.pi`・`~/.dsh`・キーチェーンには触れていない（そもそもどちらのフォルダも無かった）。
- **鍵は使っていない。** 手元に OpenAI 互換と Anthropic Messages 互換を話すモック LLM を立て、合図の語に応じて、普通の返答、ツール呼び出し、15 秒かけて流す返答、400、401、6 秒のバックグラウンドジョブを返させた。ACP は necoder と同じ `initialize`（`clientInfo`・`session.configOptions.boolean`・`elicitation.form`）を送るプローブで、生のフレームを時刻つきで記録した。
- **necoder の実コード越しの確認**: `acp_client` に一時的な例を足して `run_session_on` で起動し、necoder が受け取る `AgentEvent` を見た（例はコミットしていない）。

## ① Pi はサブスクで使えるか

### 1.1 ログインできるサブスク（Pi 1.0.0）

ログインは対話の `pi` を起動して `/login [provider]` で行う。`pi login` というサブコマンドは無い。1.0.0 の `providers.md` にはサブスクの一覧がもう無いので、同梱の OAuth 実装（`packages/ai/src/auth/oauth/`）から拾った。

| `/login` の表示名 | 入った版 | 方式 | 各社の扱い（下の 1.2） |
|---|---|---|---|
| OpenAI (ChatGPT subscription) | 0.99.0（2026-09-29） | OpenAI 公式の Sign in with ChatGPT（OSS 向け） | ◎ OpenAI が OSS 向けに用意した経路 |
| OpenAI (ChatGPT Plus/Pro) | 以前から | Codex の OAuth（ブラウザか device code） | ◎ OpenAI が Pi を名指し |
| Kimi Code (subscription) | 0.82.0（2026-07-24） | device code | ○ 主要なエージェントでの利用を認め、名乗りの偽装は禁止。Pi は 0.84.2 から自前の名乗り |
| GitHub Copilot | 以前から | device code。Pi は VS Code の Copilot Chat を名乗る | △ 公式に対応したのは OpenCode だけ |
| xAI (Grok/X subscription) | 0.80.8（2026-07-16） | device code | △ 公式の案内は OpenCode だけ |
| Meta (Muse subscription) | 0.86.1（2026-09-20） | device code | 未確認 |
| Anthropic (Claude Pro/Max) | 以前から（1.0.0 でコード貼り付けのログインを追加） | ブラウザ。Pi は Claude Code を名乗る | ✕ 従量の extra usage になり、規約上も認められていない（1.3） |

- サブスクではない OAuth に OpenRouter（API キーを発行する）と Radius（Pi の作者 Earendil Works のゲートウェイ）がある。
- Google Gemini CLI と Antigravity のログインは 0.71.0（2026-04-30）で外された。Google は第三者のツールからの利用を規約で禁じている（1.2）。
- API キーで使えるプロバイダは `providers.md` の表に 33 行ある。DeepSeek（`DEEPSEEK_API_KEY`）、Z.ai Coding Plan（`ZAI_API_KEY`・中国版 `ZAI_CODING_CN_API_KEY`）、Kimi For Coding（`KIMI_API_KEY`）、MiniMax、Moonshot、Qwen Token Plan、Xiaomi MiMo（Token Plan を含む）、OpenRouter など、#38 の中国系コーディングプランはほぼ揃っている。表に無い OpenAI / Anthropic / Google 互換の口は `<agent-dir>/models.json` に書けば足せる。

### 1.2 各社の規約での扱い（2026-10-02 時点）

- **OpenAI**: Codex for OSS のページが "Developers should code in the tools they prefer, whether that's Codex, OpenCode, Cline, pi, OpenClaw, or something else" と Pi を名指ししている。Sign in with ChatGPT は "available to all open-source partners and selected private clients" で、"Eligible ChatGPT Plus and Pro users can use their ChatGPT plan for AI requests in participating apps"。規約本文での保証ではないが、一次資料で Pi を名指ししているのは各社で OpenAI だけ。
- **GitHub Copilot**: 2026-01-16 に "GitHub is officially supporting using your Copilot Pro, Pro+, Business, or Enterprise subscription with OpenCode."。Pi への言及は無い。Pi は `User-Agent: GitHubCopilotChat/0.35.0`・`Editor-Version: vscode/1.107.0`・`Copilot-Integration-Id: vscode-chat` を送る（Pi 1.0.0 の `github-copilot.ts`）。
- **xAI**: 2026-05-21 の告知が "Use your SuperGrok or X Premium subscription inside OpenCode." と "More open-source agents and integrations are coming soon."。Pi の名前は無い。
- **Kimi**: "Kimi Code benefits support use in mainstream Coding Agents, such as Claude Code, Roo Code, and OpenCode." と、"tampering with the client identifier (User-Agent) will be treated as a violation and may result in suspension of your membership benefits."。Pi は pi-ai 0.84.2（2026-08-14）で `User-Agent: KimiCLI/1.5` をやめ、Pi 自身の名乗りに変えた（pi-ai の CHANGELOG）。
- **Google**: Gemini CLI の規約が "Directly accessing the services powering Gemini CLI … using third-party software, tools, or services (for example, using OpenClaw with Gemini CLI OAuth) is a violation of applicable terms and policies. Such actions may be grounds for suspension or termination of your account."。2026-09-03 には有料会員の停止が報じられた（二次）。Pi はその前に外している。
- **Meta**: 第三者のツールでの扱いは見つけられなかった（未確認）。

### 1.3 Claude のサブスクを Claude Code の外で使うこと

- Claude Code の Legal and compliance:
  - "OAuth authentication is intended exclusively for purchasers of Claude Free, Pro, Max, Team, and Enterprise subscription plans and is designed to support ordinary use of Claude Code and other native Anthropic applications."
  - "Anthropic does not permit third-party developers to offer Claude.ai login into their own applications, or to route requests through Free, Pro, or Max plan credentials on behalf of their users. Moreover, developers may not collect, store, or intermediate Claude.ai credentials or session tokens"
  - "Anthropic reserves the right to take measures to enforce these restrictions and may do so without prior notice."
- **2026-04-04 の変更**（VentureBeat・二次）: 正午 PT から、サードパーティ製ハーネスではサブスクの枠が使えなくなり、pay-as-you-go の extra usage か API に移った。Pi も 0.66.0（2026-04-08）から、対話の画面で "Third-party harness usage draws from extra usage and is billed per token, not your Claude plan limits." と警告する（`warnings.anthropicExtraUsage` で消せる）。**この警告は対話モードにしか無く、pi-acp 経由（RPC）では出ない。**
- **6/15 の停止告知**: Agent SDK の利用を別枠のクレジットに移す計画は止まり、ヘルプセンターは "Claude Agent SDK, `claude -p`, and third-party app usage still draw from your subscription's usage limits." としている。これは Agent SDK・`claude -p`・SDK で作った他社アプリの話で、necoder の Claude Code（`claude-agent-acp` は Agent SDK）はこちらに入る。Pi は Agent SDK を使わず、Messages API を直接呼ぶ。Pi の開発元（earendil-works）のメンバーの mitsuhiko も、2026-06-16 に "Unfortunately that does not extend to the use of coding agents." と答えている（Pi #5791）。
- **Pi の実装**: Anthropic へのサブスクの要求に、Claude Code の OAuth client ID、`user-agent: claude-cli/<版>`・`x-app: cli`、system の先頭に "You are Claude Code, Anthropic's official CLI for Claude." を付ける（Pi 1.0.0 の `anthropic.ts`・`anthropic-messages.ts`。手元の配布物でも確認）。上の規約文の「第三者が Free/Pro/Max の資格情報で要求を通す」に当たる。
- **まとめ**: Claude のサブスクは、Pi ではプランの枠で使えない。従量で払うことになるうえ、規約に照らしても勧められない。Claude は necoder の Claude Code で使う。

### 1.4 ログインの場所と保存先、pi-acp から効くか

- 保存先は `<agent-dir>/auth.json`。agent dir の既定は `~/.pi/agent` で、`PI_CODING_AGENT_DIR` で変えられる。ファイルは 0600・フォルダは 0700 で、`proper-lockfile` でロックしてから更新する（複数の pi が同時に token を更新しても壊れない）。OS のキーチェーンは使わず、OAuth の token は平文の JSON。API キーだけは `"!security find-generic-password …"` のようにコマンドで取れる。
- 確かめる道具は `pi auth check|print-api-key|print-bearer-token`。`check` は `ready` / `not_ready` / `invalid` を終了コード 0/1/2 で返すが、`--provider` か `--model` の指定が要る（Pi 1.0.0 の `cli.md`）。どのプロバイダを使うかを知らない necoder の「ログイン済みか」の判定には、そのままでは使えない。
- **pi-acp から効く。** pi-acp は PATH の `pi` を `pi --mode rpc --no-themes` で、受け取った環境変数のまま起動するので、同じ `auth.json` を読む。対話の `pi` で `/login` すれば、そのまま ACP 側でも使える。`PI_ACP_PI_COMMAND` で起動する pi を差し替えられる。
- pi-acp の `authMethods` は 1 つだけ: `{id: "pi_terminal_login", type: "terminal", args: ["--terminal-login"]}`。`pi-acp --terminal-login` は対話の `pi` を起動するだけで、その中で `/login` する。
- 実測: 資格情報が無いと `session/new` が -32000 "Authentication required: Configure an API key or log in with an OAuth provider." で返る。pi 本体が PATH に無いと -32603 "Could not start pi: executable not found … Install it via `npm install -g @earendil-works/pi-coding-agent` …" で返る（pi-acp は pi を依存に持たない）。

## ② dsh（DeepSeek Harness）

### 2.1 配布と導入

- npm の `@deepseek-ai/dsh`（コマンド `dsh`）。MIT。公開されている版はすべて rc か alpha で、`latest` = `next` = 0.2.0-rc.2（2026-09-29）。GitHub の Release（`dsh-v0.2.0-rc.2`）も prerelease。
- `dsh` はプロファイル（部品の組み合わせ）を選んで起動する作りで、`web`（Web UI。README の入口は `npx @deepseek-ai/dsh web` → `http://127.0.0.1:3080`）・`tui`・`headless`・`acp` が同梱されている。
- ほかに macOS arm64 のデスクトップ版（Homebrew cask `deepseek-harness` 0.2.0-rc.2、配布元 download.deepseek.com）と、PyPI の `deepseek-harness-sdk` 0.1.5rc1（Python 3.10 以上）がある。Homebrew の formula `dsh` は別物（Dancer's shell）なので注意。
- Node はリポジトリの指定が `^22.19.0 || >=24.0.0`。

### 2.2 認証と設定

- データの置き場は `$DSH_HOME`（既定 `~/.dsh`）。API キーは `$DSH_HOME/.credentials.yaml` に入る。書くのは Web UI の Settings → Models か `dsh-acp login`。起動時の `DEEPSEEK_API_KEY` が保存済みの鍵より優先される。
- **DeepSeek 公式の経路は Anthropic Messages 形式**。既定の接続先は `https://api.deepseek.com/anthropic`、`DEEPSEEK_BASE_URL` で変えられるが Messages 互換の URL でなければならない（`dsh-llm-deepseek` の README）。dsh-acp の README は今も「OpenAI 互換の上書き」と書いていて古い。実測でも要求は `POST /v1/messages`（`x-api-key`・`anthropic-version`）だった。
- `deepseek-account` 経路は DeepSeek アカウントでのサインイン。API キーには落ちず、Platform の残高から引かれる（`ACCOUNT_QUOTA` と補充の導線がある）。
- 他社のモデル（GLM・Kimi など）は dsh 側にプロバイダの設定（Web UI の Models、または pi-ai を包む `dsh-llm-pi-ai`）が要る。実測では `ZAI_API_KEY`・`KIMI_API_KEY`・`ANTHROPIC_API_KEY`・`OPENAI_API_KEY` を環境に置いただけでは、dsh-acp のモデル一覧は DeepSeek の 2 つのままだった。OAuth で入るプロバイダは "Providers that sign in with OAuth, such as Codex, are not supported here yet."（`providers.md`）。`OPENAI_BASE_URL` を読む箇所は見つからなかった。

### 2.3 料金（サブスク・定額）

サブスク・定額・Coding Plan は無い。料金ページは従量だけで、"The corresponding fees will be directly deducted from your topped-up balance or granted balance" とある。100 万トークンあたりの USD（ピーク / オフピーク）:

| | deepseek-flash（V4.1-Flash） | deepseek-v4-pro（V4-Pro-0813） |
|---|---|---|
| 入力（キャッシュヒット） | 0.006 / 0.003 | 0.044 / 0.022 |
| 入力（キャッシュミス） | 0.30 / 0.15 | 1.32 / 0.66 |
| 出力 | 1.20 / 0.60 | 3.96 / 1.98 |

ピークは月〜金の 01:00–04:00 と 06:00–10:00 UTC（中国の祝日を除く）で、それ以外はピークの半額。コンテキストは 100 万トークン、出力は最大 384K。dsh 自体は無料（MIT）。

### 2.4 セッションの記録の送信

- `dsh-base` に入っている `session-log-deepseek` が既定で有効で、DeepSeek 公式経路の要求に `dsh_session_log`（セッションのイベントログ）を付けて送る。README の言い方は "Disable it only when the official API must not receive a Session-log suffix."。
- 実測: dsh-acp（同梱 0.1.7-rc.2 と手元の 0.2.0-rc.2）でも dsh 公式の ACP でも、すべての要求に `dsh_session_log` と `dsh_plugin_packages`（使っているプラグインの一覧）が付いていた。最初の要求の `dsh_session_log` は約 28.7 KB あり、利用者の発話（`user/message`）、system、権限プリセット、`request/context` などのイベントが入っていた。
- 止め方: Web UI の Settings → General、または `$DSH_HOME/cordis.patch.yml` に次を書く。dsh-acp の両方のランタイムで `dsh_session_log` が消えることを実測した（`dsh_plugin_packages` は別の部品なので残る）。

```yaml
- id: session-log-deepseek
  config:
    enabled: false
```

### 2.5 公式とコミュニティの 2 つの ACP

| | dsh 公式（`dsh --profile acp`） | コミュニティ製（`@openma/deepseek-harness-acp`、コマンド `dsh-acp`） |
|---|---|---|
| 作り手 | DeepSeek。2026-08-10 から公開 | openma-ai。npm の maintainer は 1 人、2026-08-14 から 41 版 |
| 位置づけ | 自動化専用。2026-07-23 の設計ノートで、エディタ向けの面を外し "it no longer claims compatibility as a general editor entry point" | Zed などのエディタ向け。Web UI と同じ `$DSH_HOME` を使う |
| 入れ方 | `dsh` 本体に同梱 | `npm i -g @openma/deepseek-harness-acp`。dsh 本体が無くても同梱のランタイムで動く。`DSH_PATH` → `./node_modules` → PATH の `dsh` → `npm root -g` の順に探し、見つかった dsh を優先する |
| ライセンス | MIT | Apache-2.0 |
| ACP レジストリ | 無い | 無い（追加の PR #506 が 2026-08-14 から open） |
| 注意 | 特に無い | 同梱は dsh 0.1.7-rc.2（README の `0.1.5-rc.1` は古い）。手元に dsh 0.2.0-rc.2 があるとそちらを使う。0.2.0 系はアダプタの互換リストに無いが、実測では動いた |

## ③ アダプタの広告とターンの閉じ方（実測）

### 3.1 `initialize` と `session/new`

| | pi-acp 0.0.34（pi 1.0.0） | dsh-acp 0.4.35 | dsh 公式（0.2.0-rc.2） |
|---|---|---|---|
| `authMethods` | `pi_terminal_login`（terminal） | `api-key:deepseek-official`・`api-key:deepseek-account`（`NO_BROWSER` が無ければ `browser`、クライアントが申し出れば `gateway`） | 空（`authenticate` は即成功） |
| `loadSession` | true | true | false（`resume` だけ） |
| `sessionCapabilities` | list・delete | list・resume | list・resume・close |
| 画像 | 可 | 可 | 不可 |
| MCP | `http: false`。stdio も受け取るだけで pi に渡さない | stdio と HTTP をセッションに付ける | stdio と HTTP |
| `_meta` | 無い | `steering.supported: true`（Claude / Codex のアダプタと同じ `_session/steering`） | 無い |
| 資格情報が無い時 | `session/new` が -32000 | `session/new` が -32000 "Authentication required: no credential found …" | `session/new` は通り、prompt が -32603 "turn failed: … no API key for provider route …" |
| `modes` | 思考量（`Thinking: off`〜`high`。選べる段はモデルで変わる） | `read-only`・`workspace-write`（既定）・`danger-full-access` | 無い |
| 設定項目 | `model`（値は `provider/id`）・`thought_level` | `mode`・`collaboration_mode`（default / plan）・`model`（`deepseek-official::deepseek-flash` など）・`effort`（off / low / high / max）・`agent`（standard / ptc / minimal / cordis） | `model`（3 つ）・`reasoning_effort`（off / low / high / max） |
| スラッシュコマンド | compact・autocompact・export・session・name・steering・follow-up・changelog（ほかにファイルのプロンプトとスキル） | status・model・compact・feedback・goal・permission・plan（ほかにスキル） | 無い |
| `initialize` の時間 | 0.08〜0.49 秒 | 新しい HOME での初回は 6.5〜10 秒（同梱ランタイムの準備）、2 回目から 0.7 秒。手元に dsh があれば 0.5〜0.7 秒 | 0.4〜0.5 秒 |
| `session/new` の時間 | 0.3〜0.8 秒 | 0.01〜0.02 秒 | 0.04〜0.2 秒 |

### 3.2 ターン（モック接続）

| 場面 | pi-acp | dsh-acp | dsh 公式 |
|---|---|---|---|
| 普通の返答 | 最後の更新の直後に `end_turn`。応答の後の更新は無い | 同じ（会話名の更新が後から 1 つ来る） | 同じ |
| ツール（`echo`） | 権限の問い合わせ無しで実行。出力は Zed 向けの `_meta.terminal_output` だけ | 出力は本文（`content`）に入る。`workspace-write` の範囲なので問い合わせ無し | 出力は本文に入る（題は `bash`、種別は `other`） |
| 15 秒かけて流れる返答 | 流れてくる順にその場で届く | **最後に 1 塊で届く**（両ランタイム） | 最後に 1 塊 |
| 2.5 秒で取り消し | すぐ `cancelled` | 7 ms で `cancelled`。途中までの本文は応答の後に 1 塊で来る | すぐ `cancelled` |
| モデル側の 400 | **本文も説明も無い `end_turn`** | -32603 "turn failed: mock bad request" | 同じ |
| モデル側の 401 | **本文も説明も無い `end_turn`** | -32603 "turn failed: Invalid API key (mock)" | （未測） |
| 6 秒のバックグラウンドジョブ | 測れない（Pi に無い） | 0.09 秒で `end_turn`。ジョブが終わると、プロンプトの外で追いのターンが走る。頭に `session_info_update`（`_meta.dsh.event: "user/message"`, `source: "tool-jobs"`）が付く | 同じ。合図は無い |
| ターン中に pi を kill | **ターンが閉じない**。取り消しを送っても閉じず、次のプロンプトもその後ろで止まる | 当てはまらない（同じプロセスの中で動く） | 当てはまらない |
| `session/load` | 0.16 秒。履歴を再生する | 0.03 秒。履歴を再生する | 無い |

- **dsh の本文がトークン単位で流れない理由**: dsh の現行のセッションイベント（v2）は `assistant/chunk` を出さず、流れた本文を確定した `assistant/message` に埋め込む（`dsh-session-format-v1-to-v2` の README）。dsh-acp の差分の処理は旧形式向けなので、実モデルでもメッセージ単位でしか届かない。長い返答は終わるまで画面に何も出ない。
- **dsh の失敗したターン**: 失敗した発話が履歴に残り、次の発話と 1 つの user メッセージにまとめて送られる。
- **pi-acp が失敗した時の挙動**は、upstream の issue と一致する: エラーが空の `end_turn`（#98・#135・#92・#43）、pi の死を検知しない（#82）、拡張コマンドのプロンプトが返らない（#84。Pi 0.99 の RPC は実行を始めなかったプロンプトに `disposition: "handled"` を返すが、pi-acp はこれを見ない）、思考量が `modes` と設定項目で二重（#95）、ツールの境目でターンが止まる（#154）。open な issue は 43 件。

### 3.3 necoder に挿した時に出る差

necoder の `run_session_on` 越しに流して確かめた。どちらもセッションは開け、返答、ツール、取り消しの各ターンは `TurnStarted` から `TurnEnded` まで通る。そのうえで、組み込みのエージェントとは次の差が出る。

| | Pi（pi-acp） | dsh（dsh-acp） |
|---|---|---|
| 権限モードのピル | `modes` を権限モードとして出すので「Thinking: medium」などが並び、思考量のセレクタと二重になる（`agent_panel.rs` の `AgentEvent::Modes`） | read-only / workspace-write / Full access がそのまま並ぶ。ただし「聞かずに進める」の既定は効かない（`is_bypass_mode` は `danger-full-access` を拾わない） |
| シェルの出力 | 出ない（`_meta.terminal_output` を読まない） | 出る |
| エラー | 400 も 401 も空のターンで終わる。再ログインの案内も出ない | 理由つきの「エラー: …」。モックの 401（"Invalid API key"）は `is_auth_failure` が拾い、再ログインの案内になった。DeepSeek の実際の文言で拾えるかは未確認。`session/new` の "Authentication required: no credential found …" は拾えず、一般のエラーになる |
| 最初の返答 | 頭に pi の起動情報（`pi v1.0.0 ---`）が混ざる。Pi の設定 `quietStartup: true` で消える | 混ざらない |
| ターンごとのトークン | 出ない（コンテキストのメーターは出る） | 出ない。dsh-acp は ACP の unstable な `usage`（`unstable_end_turn_token_usage`）を返すが、necoder が読むのは `_meta.quota` |
| Chat モード | **Pi はツールの前に許可を求めない**（Pi の `security.md`）ので、Chat のフォルダの守り（`chat_core::policy`）が効かない | 問い合わせが来るので守りが効く。既定の `workspace-write` は cwd の外への書き込みを sandbox で止める |
| MCP | necoder が渡す MCP サーバは Pi に届かない（Fleet の道具も） | 届く（広告と README から。道具の呼び出しまでは測っていない） |
| 自走のターン | 無い | 待機中の更新として本文が届く。実行中の表示は立たない |
| 会話名 | 付かない | dsh がモデルに 1 回余分に聞いて付ける |

### 3.4 zeron が捨てた理由との違い

zeron は、アダプタが裏の作業でターンを開いたままにすることを理由に、Claude と Codex と OpenCode のアダプタを捨てた（[`crates/harness/src/lib.rs`](https://github.com/zeronsh/zeron/blob/80b946b153e431f8e3fdd7a99faf81b23c77706c/crates/harness/src/lib.rs) の冒頭、[`docs/research/acp.md`](https://github.com/zeronsh/zeron/blob/80b946b153e431f8e3fdd7a99faf81b23c77706c/docs/research/acp.md)）。Pi についても 2026-09-29 に pi-acp をやめ、`pi --mode rpc` を直接話す形へ移った（[`docs/research/pi-rpc.md`](https://github.com/zeronsh/zeron/blob/80b946b153e431f8e3fdd7a99faf81b23c77706c/docs/research/pi-rpc.md)）。

今回の測定では、Pi と dsh のどちらでも、ターンが開いたままになることは無かった。Pi に裏の作業は無く、pi-acp は Pi の `agent_settled`（再試行や圧縮まで済んだ本当の終わり）で閉じる。dsh はむしろ逆で、ジョブを待たずにすぐ閉じ、後から自走のターンを流す。necoder はアイドル中の更新も読む（Codex の `/goal` と同じ経路）ので、本文は落ちない。

困るのは pi-acp が失敗した時だ。モデル側のエラーは中身の無い `end_turn` として閉じたように見え、pi が死んだ時と `handled` の時はターンが二度と閉じない。necoder のターン待ちには取り消しの後も時間切れが無いので、後者のスレッドは実行中の表示のまま残る。

## ⑤ 上位に置く案

### 5.1 今回の判断

今回は Pi も dsh も `const AGENTS` に足さない。理由は 2 つある。

1. **`const AGENTS` に足すだけでは composer に出ない。** composer に並ぶのは、ログインを確かめられた組み込みと、足したエージェント全部（`settings::selectable_agent_labels`）。組み込みのログイン判定は、起動時は `AgentKind::configured_auth_state`（ファイルと環境変数を見る `match`）で、ここに `pi` と `dsh` の分岐が無いと `SignedOut` になる。設定画面を開いた時の試し起動（`probe_acp_session`）は、PATH か Zed のキャッシュにあるアダプタしか使わないので、npx だけで入れた人はそこでも通らない。いまのカスタム追加は常に並ぶので、足すだけだと後退する。
2. **アダプタがまだ、組み込みとして勧められる状態に無い。**
   - Pi: エラーが空のターンになる、pi が落ちるとターンが閉じない、シェルの出力が見えない、思考量が権限のピルに出る、necoder の MCP が届かない、Chat の守りが効かない。どれも 3.2 と 3.3 で実測した。
   - dsh: 本体が rc で、アダプタは 1 人で作っているコミュニティ製。本文がトークン単位で流れず、レジストリにも載っていないので、necoder が版を焼き込んで追うことになる。既定で会話の記録を DeepSeek に送ることも、組み込みとして勧めるなら最初に知らせなければならない。

### 5.2 いま上のほうで使う方法（コードの変更なし）

MANUAL の「Pi と DeepSeek Harness を使う」に手順を書いた。要点:

- **Pi**: `npm i -g @earendil-works/pi-coding-agent` → ターミナルで `pi` → `/login`（ChatGPT・Copilot など）→ 設定 → AI エージェント → ＋ エージェントを追加 → 「pi ACP」。`~/.pi/agent/settings.json` に `"quietStartup": true` を入れると最初の返答に起動情報が混ざらない。
- **dsh**: `npm i -g @openma/deepseek-harness-acp` → `dsh-acp login` → settings.json の `agent_servers` に `"dsh": { "name": "DeepSeek Harness", "command": "dsh-acp" }`。記録の送信は `~/.dsh/cordis.patch.yml` で止める（2.4）。
- どちらも設定 → AI エージェントで「既定」にすれば、新しいスレッドはそれで始まる。

### 5.3 上げる時の案（本人の判断）

**並び順**: Claude Code → Codex → **Pi** → **DeepSeek Harness** → GitHub Copilot → Qwen Code → OpenCode → Kimi CLI → Grok Build。Pi を先にするのは、ChatGPT・Copilot・中国系のプランまで 1 つのハーネスで受けられ、#38 の「接続」の軸に一番合うから。

**`AgentKind` の案**（`AGENT_LABELS` も同じ順に足す）:

```rust
// Pi（Earendil Works・MIT）: ACP はコミュニティ製の pi-acp（MIT・公式レジストリの `pi-acp`）。
// pi-acp は PATH の `pi` を `pi --mode rpc` で起こすだけなので、本体も要る。
AgentKind {
    id: "pi",
    label: "Pi",
    cli_bin: "pi",
    bin: "pi-acp",
    registry_id: Some("pi-acp"),
    package: Some("pi-acp@0.0.34"),
    extra_args: &[],
    install_cmd: "npm i -g @earendil-works/pi-coding-agent pi-acp",
    login_cmd: "pi", // 開いた画面で /login
    icon: None,
    brand_color: 0xd0_d5_db,
    monogram: "Pi",
},
// DeepSeek Harness（DeepSeek・MIT）: ACP はコミュニティ製の dsh-acp（Apache-2.0・レジストリ未掲載）。
// 本体が無くても同梱のランタイムで動き、PATH に dsh があればそちらを使う。
AgentKind {
    id: "dsh",
    label: "DeepSeek Harness",
    cli_bin: "dsh-acp",
    bin: "dsh-acp",
    registry_id: None,

    extra_args: &[],
    install_cmd: "npm i -g @openma/deepseek-harness-acp",
```

- **id**: dsh を `"dsh"` にすると、MANUAL の例どおり `agent_servers.dsh` を書いている人の設定は、組み込みの起動を上書きする設定に変わる。表示名も同じ DeepSeek Harness なので、前のスレッドも相手を見失わない。
- **アイコン**: 入れていない。Pi と DeepSeek のロゴの出所とライセンス（商標）を確かめてからにする。dsh-acp 同梱の `assets/icon.svg` は黒 1 色で、パッケージの Apache-2.0 はロゴの使用許諾を意味しない。それまではモノグラムで出る。

### 5.4 上げる前に一緒に要るもの

`const AGENTS` の外の変更（今回の範囲の外なので入れていない）:

1. `AgentKind::configured_auth_state` に分岐を足す。Pi は `<PI_CODING_AGENT_DIR か ~/.pi/agent>/auth.json` か鍵の環境変数、dsh は `$DSH_HOME/.credentials.yaml` か `DEEPSEEK_API_KEY`。無いと 5.1 の 1 のとおり composer に出ない。Claude の `claude auth status` に当たる確かめ方は、Pi では `pi auth check` がプロバイダの指定を要るので使いにくく、試し起動（`session/new` がモデル 0 件なら -32000）に任せるのがよい。
2. `AgentKind::login_command` に `pi`（→ `/login`）と `dsh-acp login` を足す（再ログインのカードの案内）。
3. Pi の `registry_id` を `pi-acp` にすると、`pi-acp` を見本のレジストリ項目に使っているテスト（`custom.rs`・`settings.rs`・`add_agent.rs`）を別の項目に替える必要がある。レジストリから「pi ACP」を足していた人のスレッドは、表示名が Pi に変わるので相手を見失う。
4. necoder 側で吸収できる差:
   - `modes` が思考量と同じ選択肢なら、権限のピルに出さない（Pi）
   - `is_bypass_mode` に `danger-full-access` を足す（dsh）
   - `is_auth_failure` に ACP の標準文言 "authentication required" を足す（dsh の `session/new`）
   - ターンの `usage`（ACP の unstable）も読む（dsh）
   - `_meta.terminal_output` / `terminal_exit` を読む（Pi のシェル出力。Zed の流儀）
   - 許可を求めないエージェントを Chat で選べないようにするか、警告する（Pi）
   - 取り消しの後に一定時間閉じないターンは、プロセスを畳む（pi-acp の詰まり）

アダプタ側に待つもの:

- pi-acp: エラーを ACP のエラーとして返す（#135）、pi の死の検知（#82）、`disposition: "handled"` への対応（#84）。zeron のように `pi --mode rpc` を直接話す手もあるが、necoder が ACP とは別の接続を 1 本持つことになる。
- dsh-acp: v2 のイベントでのトークン単位の配信、dsh 0.2.0 系への追従（同梱を上げる bot の PR #32 が未マージ）、レジストリへの掲載（#506）。dsh 本体の正式版。
