## 合意した体験

- 左バー下部、設定の上に Lucide `smartphone-user-round` を常設する。ツールチップは「スマホ連携」。
- 初回だけアイコンの横に「スマホからAIの進捗確認・承認ができます」と「接続する」「閉じる」。閉じたことを保存する。
- アイコンから接続用QR、登録端末一覧、接続解除へ進める。
- 初回接続はQRを読み取っただけでは使えず、PC側で端末を承認する。
- スマホで利用開始・一定時間の放置後はパスキーで本人確認する。Face ID / 指紋 / PIN などの選択はOSと認証器に任せる。

## セキュリティ境界

既存の端末間暗号化と共有プロジェクト制限を維持する。リレーは暗号文の中継にとどめ、
WebAuthn の登録・認証チャレンジ生成、Origin / RP ID / 署名 / UV / チャレンジの検証はPCのホストで行う。
署名検証には保守された WebAuthn ライブラリを使い、暗号検証を自作しない。

1. QRは5分有効。読み取り後は既存の暗号化経路を確立し、QR秘密を更新する。
2. スマホはパスキーを登録する（`userVerification: required`）。PCの承認前はプロジェクト名・会話・コードを送らない。
3. PCには端末名と、スマホにも表示する照合コードを出す。コードを照合したうえで承認・拒否する。
4. PC承認後も、新しい接続ではパスキーによる認証を求める。登録成功だけを利用時の認証の代わりにしない。
5. 認証状態は暗号セッションごとに保持し、接続変更・画面を閉じる・5分の無操作でロックする。
   PC側にも5分の無操作期限と最大15分の認証期限を設ける。heartbeatや配信は無操作期限を延長しない。
6. PC側のデータ配信・操作・Push購読を認証状態で制限する。スマホのボタンを無効にするだけでは済ませない。
7. 端末解除はローカルの登録を先に失効させ、接続中チャネルも閉じる。リレーが不通でも失効を完了する。
8. 旧方式の端末は本人確認を迂回させず、再ペアリングを案内する。
9. WebAuthn非対応・キャンセル・認証失敗時はロックを維持し、弱い認証への自動フォールバックはしない。

QR漏えい前の登録競争はPCでの照合・承認で防ぐ。PWA配信元の悪意あるJavaScriptや、
侵害済みPC/OSに対する防御まで保証するものではない。パスキーの登録先・同期挙動はOSの仕様に従う。

## 実装結果

- 入口は `workspace/phone_connection.rs` とレール。`phone_hint_seen` をユーザー設定へ保存する。
  案内はEditorでだけ表示し、FleetのTask追加やChatの作業面に重ねない。アイコンは3モードに常設する。
- 設定のスマホ連携ページを2秒ごとに更新する。ページが描画されていない間はpollを連鎖させない。
  このページを開くだけではエージェントCLIの可用性調査を起動しない。
- スマホがパスキー登録を終えたらPCの使用済みQRを退け、照合コードと承認ボタンを見せる。
- PC承認は永続化を終えてからメモリ上でも有効にする。保存失敗時にアクセス権を付与しない。
- 認証前の`confirm`、heartbeat、pollからも会話を配信しない。暗号化中のロック・失効を送信直前にも確認する。
- ホストの保守ライブラリは `@simplewebauthn/server@14.0.3`、ブラウザ側は `@simplewebauthn/browser@14.0.0`（MIT）。
  ブラウザ用モジュールは自己配信する。ビルドで依存のライセンス一覧も再生成する。
- 初回QR発行時だけ未設定のローカルホスト設定を作る。新版CLIは旧ホストを検出したら、ローカル認証して
  停止・新版起動する。既存設定・接続先・管理鍵は上書きしない。旧端末は再登録が必要。

### 継続検証での修正（2026-10-23）

- 認証の永続化中にロックされても、同じチャネル上では古い認証が完了して解錠できる競合を再現して修正。
  ロックごとに認証の世代を更新し、チャレンジ生成・署名検証・保存の前後で同じ世代か確認する。
- 暗号化中にロックされた `unlocked` 通知が送られるケースを再現して修正。
  解錠通知にも、会話と同じ送信直前の認可チェックを適用する。
- PCホストだけが切断され、スマホとリレーの接続が残ったときに会話・下書きが残るケースを再現して修正。
  ホストの切断・再接続通知を受けた時点で消去し、最新の暗号接続とパスキー認証を待つ。
- Chromium / WebKitで、ホスト切断時の消去と再認証、ページ退避・復帰イベント、5分の無操作、
  操作を続けた場合も15分でロックする動作を追加検証。
  時刻試験はheartbeatによる切断をタイムアウトの成功と誤認しないよう、壁時計と1秒タイマーを使う。
  ページ復帰イベントの再現は実機OSのホーム画面PWA復帰の検証とは区別する。

## 実機の受け入れ手順（未実施）

新版PWAの固定HTTPS検証先と新版PCホストを揃え、実際の会話を含まない専用プロジェクトで確認する。
スマホからPCのLAN内HTTPアドレスを開く方法では、パスキーの確認を代用できない。
本番への配信はこのローカル作業に含めない。

| 操作 | 確認する結果 |
| --- | --- |
| iPhoneのSafariとホーム画面PWA、AndroidのChromeとホーム画面PWAで登録 | OSが提示する顔・指紋・PIN等で登録できる。PC承認前は会話が出ない |
| PCとスマホの6桁コードを比較し、承認 | 登録だけでは解錠せず、利用時のパスキー認証を求める |
| 本人確認をキャンセルし、再試行 | キャンセル中は会話が出ず、再試行で利用できる |
| 5分放置／操作を続けて15分経過 | いずれもロックし、会話・差分・下書きを消去する |
| アプリ切替、画面ロック、ホーム画面PWAの終了・復帰 | 復帰時に前の表示を再利用せず、本人確認を求める |
| PCホストの停止・再起動、Wi-Fiと携帯回線の切替 | 切断時に表示を消し、復帰後は再認証する。操作を自動再送しない |
| PCから端末を解除し、スマホで再接続 | パスキーを保持していても利用できない。再接続するには新しいQRが必要 |
| Windowsで同じ接続・承認・解除 | ホスト起動、保存先ACL、名前付きパイプを含めて動く |

端末名、OS・ブラウザのバージョン、通常タブ／ホーム画面PWAの別と結果を記録する。
生体情報、パスキーの秘密鍵、QR、接続トークンは記録しない。
